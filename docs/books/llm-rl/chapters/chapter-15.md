# 第 15 章 长程信用分配与并行多智能体编排

<p class="chapter-summary">剖析多轮百步轨迹下稀疏奖励信用分配的四大缓解路径，深入拆解 2026 年 Kimi K2.5 的并行智能体强化学习（PARL）：为何“冻结子智能体、只训练编排者”能绕开多智能体信用困境，以及为何效率标尺要从总步数转向关键路径步数。</p>

在单轮数学题里，一条回复大约几千个 token，哪怕只给末尾 1 bit 奖励，GRPO 靠大组采样与大量题目的统计平均依然能稳稳收敛。但把回合拉长到真实软件工程或深度研究 Agent：一条轨迹横跨 **50–1,000 轮工具调用**、跨越数十万 token，可能前 25 轮的精准排障全对，仅仅因为第 26 轮忘记处理一个边界空指针导致最终测试挂掉。

本章聚焦 Agentic RL 中最具挑战的两个问题：**超长程轨迹里的信用分配**，以及**从串行单智能体迈向并行多智能体编排**。

---

## 15.1 百轮交互下的稀疏奖励困境与四条缓解路径

当回合步数 $H$ 攀升到几十甚至数百轮，且只在末尾拿到一个标量 $r(\tau) \in \{0, 1\}$ 时，单纯把同一优势广播给全部 50 轮动作会遭遇严重的**信噪比稀释**：
- **早期好决策被后期失误连坐**：早期精准定位 Bug 文件的 `grep` 动作在最终失败轨迹中吃到负梯度；
- **晚期无效摸鱼搭顺风车**：某条碰巧通过测试的轨迹里夹杂了 10 轮毫无意义的重复读取，这些冗余动作却跟着拿到了正梯度。

目前工程与研究界主要通过四条互补路径压缩长程信用分配方差：

1. **过程里程碑与分层塑形奖励（Milestone / Shaped Rewards）**：
   在保证最终目标权重占绝对主导的前提下，给可客观验证的中间里程碑赋予温和辅助信号——例如代码修复中“成功复现原 Bug”“补丁通过语法/编译检查”“通过部分单元测试（连续通过率而非全有全无）”。必须严防里程碑被刷分（例如反复制造并修复简单语法错误），因此辅助奖励应设定严格上限或仅按“首次达成”一次性计分（基于势函数的奖励塑形思想，Potential-based Shaping）。
2. **利用环境报错做自蒸馏信用分配（SDPO 扩展）**：
   多轮 Agent 环境天然盛产高信息密度的文本反馈 $f$（第 10 章）：编译器报错、单测断言失败日志、API 返回的 `400 Bad Request` 详情。把这些报错喂给自我教师 $\pi_\theta(\cdot\mid x, f, \text{history})$，能精准把负优势压在写出错误参数或错误代码行的那几个关键 token 上，而完全放过前面正确的排查步骤。
3. <strong>轮级 Critic 或前缀分支采样（Turn-Level Tree Rollout）</strong>：
   相比为几万个 token 训练逐 token Critic，仅在<strong>轮次边界（Turn Boundary）</strong>估计状态价值 $V_\psi(s^{(h)})$，或者从共享关键前缀分叉采样多个后续分支（类似蒙特卡洛树展开），能以低得多的复杂度把信用定位到具体某一轮决策。
4. **多奖励解耦归一化（GDPO）**：
   当同时优化“最终任务完成度 + 工具调用格式规范 + 步数/耗时效率”时，采用第 10 章的 GDPO 分别归一化各维度奖励，避免“步数短”这类廉价奖励压垮“真正把任务做完”的核心目标。

## 15.2 并行多智能体 RL：Kimi K2.5 PARL 深度拆解

- **出处**：Kimi Team，*Kimi K2.5: Visual Agentic Intelligence*（2026-02，arXiv `2602.02276`）及官方技术博客（2026-01）。

面对需要广泛调研上百个来源、或同时排查大型代码库多个模块的复杂长程任务，单智能体串行一步步执行面临两堵硬墙：
- **上下文爆炸**：所有子任务的中间网页、文件与报错全部堆进同一条上下文，很快冲破窗口上限并稀释注意力；
- **墙钟延迟不可接受**：串行执行 100 次工具调用需要数十分钟，交互体验崩溃。

如果让多个智能体并行协作，传统多智能体强化学习（MARL）立刻会撞上更可怕的难题——**多智能体信用分配（Multi-Agent Credit Assignment）与非平稳性（Non-stationarity）**：任务最终成功了，到底是主编排者拆分得好，还是 20 个子智能体里的第 7 号立了大功？如果所有子智能体同时更新参数，彼此眼中对方的行为分布天天在变，训练极易发散崩溃。

### 核心设计 1：只训练编排者，冻结全部子智能体
- 主模型扮演**编排者（Orchestrator）**，可以动态决定派生多少个子智能体、给每个子智能体分配什么子任务与角色，再汇总所有子智能体返回的精炼结论（官方博客展示了最多 **100 个子智能体、1,500 步协同**的规模）；
- **训练时彻底冻结子智能体，子智能体的内部轨迹不进入策略梯度优化目标**——从数学视角看，每个子智能体都退化为编排者环境中的一个“复杂但分布平稳的工具调用”，从而彻底避开了多智能体信用分配与联合训练发散难题！
- **并行策略完全由 RL 学出**：系统不硬编码“何时该拆分子任务、该拆几路”，而是让编排者在真实任务奖励与延迟约束下，自己学会判断哪些简单问题一步直答、哪些独立子问题应该并发扇出、哪些强依赖步骤必须串行等待。

### 核心设计 2：效率标尺升级——关键步数（Critical Steps）
传统的长度惩罚或步数惩罚盯着的是“全流程消耗的总 token 数或总工具调用次数”。如果在多智能体里继续惩罚总步数，编排者会因为怕扣分而不敢派生并行子智能体，退化回缓慢的串行单打独斗。

PARL 借用并行计算中的<strong>关键路径（Critical Path）</strong>概念，定义整次多智能体协同的延迟度量为<strong>关键步数（Critical Steps）</strong>：
- 在每一轮编排者并发派生 $K$ 个子智能体的阶段，本阶段计入关键路径的步数不是 $\sum_{k=1}^K \text{steps}_k$，而是最慢那一路的 **$\max_{k=1\dots K} \text{steps}_k$**；
- 于是 RL 激励编排者既把可独立的工作拆开并行（大幅压缩关键路径），又把各路子任务拆得**负载均衡**（避免 9 路 2 步完事、1 路跑 30 步拖垮整轮关键路径）。

Kimi 团队报告称，在复杂长程研究与工程任务上，PARL 相对单智能体串行执行最多将端到端执行时间缩短约 **4.5 倍**（作者自报）。

::: tip 范式启示：Agent 效率指标的代际迁徙
- **2024 推理元年**：关心单个回复的准确率 $\text{pass@}1$；
- **2025 长 CoT 时代**：开始关心“每道题消耗的总思维链 token 数”与过思考抑制；
- <strong>2026 并行 Agent 时代</strong>：系统效率标尺正式转向<strong>关键路径步数（Critical Steps）</strong>与端到端墙钟延迟。
:::

解决了多轮建模与并行编排，落到大规模集群真正开跑时，还有一个比算法更让人头疼的现实问题：**成百上千个隔离沙箱如何稳定并发？动辄耗时几分钟的超长轨迹怎么避免拖死整群 GPU？** 下一章我们拆解规模化环境工程、课程学习与异步 Agent RL。
