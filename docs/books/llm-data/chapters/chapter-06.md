## 6.1 打破“网页数据墙”：预训练改写合成与事实锚定防线

互联网上大量蕴含珍贵专业知识的网页（如医生博客、工程排障帖、课程讲义草稿）之所以不好学，并非缺乏信息，而是**信息密度极低、行文松散夹杂废话、因果步骤跳跃**。<a class="term-ref" href="/books/llm-data/glossary#synthetic_rephrasing" title="利用强模型将原始高信息量但行文杂乱的网页重写为教科书体、问答对、科普摘要或思维推导格式以放大知识可学性">预训练改写合成（Synthetic Rephrasing）</a>的核心洞察在于：**用强开源模型把“高知识、低可读性”的天然语料重塑为“高信噪比、结构化、多视角”的可学教材**，在物理意义上打破同一份源文档的重复衰减魔咒。

三大里程碑范式层层递进：
1. **Phi 教科书化合成（Textbook-style Generation）**：率先证明几十亿到几百亿高密度教科书与分步练习题，可让 1B–3B 小模型在推理与编程上越级挑战十倍参数对手。但早期纯凭主题词无源自由生成容易出现分布窄化与知识幻觉。
2. **WRAP（Web Rephrase Augmented Pre-training）**：确立了**“基于真实网页锚定改写”**的黄金范式——输入一篇原始网页，用多套系统提示词（维基百科中立风格、问答对话体、面向本科生的讲解稿、核心要点提炼）同步改写。实测表明，将原始网页与改写版本联合训练，可把预训练样本效率直接提升 **2×–3×**，且跨视角改写后的文档在梯度方向的正交性上远优于单纯把原文档重复读第 2 轮！
3. **Nemotron-CC 规模化多视角蒸馏**：将改写彻底工业化——先用第 5 章的集成打分器把网页分桶：对**中低分但含零散事实**的网页执行“降噪提纯摘要（Distill）”，对**高分专业页面**批量衍生出“多跳问答对（Diverse QA）”、“提取核心知识清单（Extract Knowledge）”与“重述推演（Rephrase）”等 4–5 种体裁，一口气合成出数万亿高有效信息密度 Token。

| 改写合成体裁 | 输入源文档质量分桶 | 典型输出长度比 | 核心增益方向 | 幻觉与风格漂移防线 |
| --- | --- | --- | --- | --- |
| **教科书重排（Wikipedia / Textbook）** | 高分科普、博客、讲义 | $0.8\times\text{–}1.2\times$ | 消除行文杂音，强化概念定义与逻辑连贯性 | 禁止新增原文外专有名词与年份数字 |
| **多跳问答对（Diverse QA）** | 高分技术文档、百科、论文 | $0.7\times\text{–}1.3\times$ | 原生激活问答抽取、知识检索与指令对齐先验 | 强制每道题答案可由源段落直接推导出 |
| **去噪精炼（Distill / Extract Knowledge）** | 中低分但含实用信息的网页 | **$0.3\times\text{–}0.6\times$** | 把口水话、论坛灌水压缩为高密度事实要点清单 | 若原文无实质信息，允许模型输出 `[EMPTY]` 弃权 |
| **分步推演扩写（Step-by-step Derivation）** | STEM 习题、代码排障帖 | $1.2\times\text{–}1.8\times$ | 补全网页里跳步省略的中间代数变换与排错逻辑 | 优先接入符号/代码执行验证器过滤错误推导 |

### 事实锚定防线与离线批推理成本账

预训练合成最大的死穴，是放任模型无源编造引发幻觉放大甚至<a class="term-ref" href="/books/llm-data/glossary#model_collapse" title="模型反复在自身或同族模型生成的合成数据上递归微调且缺乏真实世界锚定时，分布尾部消失与方差发散的退化现象">模型坍缩</a>（详见第 21 章与专题 B）。工程上必须死守三条防线：
- **严格源文本锚定（Source Grounding）**：Prompt 显式约束“仅重组与解释原文事实，严禁引入原文未提及的数值、日期与引文”，并对输出执行长度膨胀比监控（如普通改写输出暴涨超原文 $2.0\times$ 即判为幻觉发散丢弃）与轻量 NLI 忠实度抽检。
- **拒绝“单一腔调退化”**：强制轮换 5–10 套异构体裁 Prompt，并坚持**累加混合（Accumulating Mix）**原则——改写语料作为天然语料的增强项并存，绝不把原始人类多样表达完全替换掉。
- **离线批推理经济账**：依托 [《LLM 推理工程》](/books/llm-inference/) 的离线高吞吐批推理（8B–32B 开源模型在 8×H100 节点上启用 FP8 + Prefix Caching + 连续批处理），全书统一基准单价为 **$0.08–$0.25 / 1M tokens**（有效留存 $\eta_{\text{pass}} \approx 70\%\text{–}85\%$）。将 **500B** 顶级源网页改写为 500B 教科书/问答合成语料（取中位 $0.12 / 1M），算力账单仅约 **$60,000**——不足一场 $10M 70B 主训练的 **0.6%**，却能换来近乎全新的 500B 超高密度有效数据 $D_U$！

## 6.2 Mid-training（退火阶段）优化动力学与 WSD 日程协同

如果说主体预训练是在用推土机夯实地基，那么<a class="term-ref" href="/books/llm-data/glossary#mid_training" title="位于大规模通用预训练末段、学习率逐步衰减至零前的关键阶段：显著上调数学、代码、长文档与改写合成数据的配比">中期训练与退火阶段（Mid-training / Annealing）</a>就是用激光雕刻刀塑造能力上限的决胜时刻。为什么在 15T 总训练量里，**仅仅调整最后 5%–10%（750B–1.5T tokens）的数据配比，就能让 MMLU、GSM8K、MATH 与 HumanEval 出现 +5 到 +15 个百分点的非线性暴涨？**

答案藏在随机梯度下降与 **WSD（Warmup-Stable-Decay）学习率日程**的耦合动力学中：
1. **Stable 稳定期（0%–90%）**：学习率维持恒定高位，参数在广阔损失地形中大步探索，高效吸收高频常识与广域世界表征；但由于步长较大，权重始终在最优盆地周围剧烈震荡，难以把精细的数学符号推理和复杂代码模式“钉死”。
2. **Decay 退火期（最后 5%–10%）**：当学习率线性、平方根或余弦衰减趋近于零时，每步更新步幅迅速收窄，模型会沿着末段数据所定义的梯度方向**永久沉降并锁定到对应的局部极小值盆地**。理论上，末段每个 Token 对最终权重位置的净影响权重被几何级放大——正因如此，把最纯净、单价最高、信息密度最大的稀缺语料留到退火期集中注入，才能撬动全周期最高的数据 ROI。
3. **WSD 带来的工程灵活性**：传统全周期 Cosine 学习率日程必须在开训前就锁死总 Token 预算 $D_{\text{tok}}$，中途想换退火配方几乎无从下手；而 **WSD 日程**让团队可以长期保留 Stable 期的中间检查点，随时分叉执行第 3 章的<a class="term-ref" href="/books/llm-data/glossary#micro_annealing" title="从预训练中间检查点分叉用少量候选数据执行短程快速退火以检出真实价值的技术">微退火评测（Micro-annealing）</a>，把几十种退火配方赛马出最优解后再一键冲刺终态退火！

## 6.3 主流基座退火配方与多阶段能力跃迁账本

纵观 **OLMo-2（Dolmino Mix）、Qwen3 与 DeepSeek-V3** 等代表性现代开源基座，虽然底层架构各异，但退火期的配方哲学高度趋同——**大幅压减通用网页占比、成倍拉升数学/代码/合成推理密度、并同步植入指令与思维链先验（但不破坏基座通用续写能力）**。以 15T 总预算为例，典型主体期与退火期的域权重 $w_m$ 迁移账本如下：

| 数据域 | 主体预训练期（0–13.5T，4K–8K） | Mid-training 退火期（13.5T–15.0T，32K–128K） | 典型公开参照实践 |
| --- | --- | --- | --- |
| **通用网页（Web）** | 60%–70%（常规过滤后全桶） | **15%–25%**（仅留 Top-10% 顶级教育/百科分桶） | OLMo-2 退火期仅留最高分 DCLM / 维基压舱 |
| **代码仓库（Code）** | 12%–18%（单文件 + 基础 FIM） | **20%–28%**（仓库级拓扑拼接 + Issue/PR + 单测） | DeepSeek / Qwen3 大幅提升跨文件仓与代码逻辑占比 |
| **数学 / STEM / 思维链** | 6%–10%（arXiv + 网页数学） | **20%–30%**（精细推导题、定理证明、合成分步解题） | Dolmino Mix 注入精细数学合成集，GSM8K 末段暴涨 10+ pp |
| **改写合成与高质问答** | 4%–8%（轻量混入防同质） | **10%–15%**（Nemotron-CC 级多视角教材与百科 QA） | 零幻觉有源改写，显著抬升 MMLU / GPQA 知识密度 |
| **原生与聚类长文档** | 5%–10%（零散长文截断打包） | **15%–25%**（32K→128K→1M 原生长文与语义聚类链） | 退火与上下文窗口扩展二合一，省去二次大退火成本 |

**退火多阶段模型融合（Model Souping）技巧**：OLMo-2 等实证进一步发现，从同一 Stable 检查点出发，用 3–5 组略有不同的高质退火子配方分别退火出多个终点检查点，最后在参数空间做**线性权重平均（Checkpoint Souping）**，能在零额外推理成本下进一步抹平单次退火方差、再赚 +0.5 至 +1.5 pp 稳健涨点。

## 6.4 长上下文（32K → 128K → 1M）三类燃料构造工程

在 Mid-training 阶段同步把上下文窗口从 4K/8K 扩展到 128K 甚至 1M，绝不仅仅是把 RoPE 的基频 $\theta_{\text{base}}$ 从 10,000 调大到 10,000,000 或换上 YaRN 算法就能自动生效的——**如果喂给长窗的依然只是把 100 篇毫无关系的 1K 网页硬拼在一起，模型根本学不会跨越 10 万个 Token 去检索和关联远距离证据！** 真实有效的长上下文数据工程必须配齐三类缺一不可的燃料：

1. **原生长文档精筛（Native Long Documents）**：从整本教材/公版书、完整大型开源代码仓（第 4 章依赖拓扑拼接）、全本上市公司年报/专利/法律判例及长篇学术综述中，专门筛出原生长度 $\ge 32\text{K}$ 且内部语义连贯的真长文。**严防“垃圾长文”**：网页里天然超过 64K 的页面往往是机器生成的巨型日志、商品目录、论坛十年灌水楼或超大 JSON 字典，必须用 Zstd 压缩比、分段信息熵和分类器首尾中三段抽检严格过滤。
2. **跨文档语义聚类拼接（ProLong / In-Context Pretraining, ICP）**：高质量原生 128K+ 文本在全网极其稀缺（常不足总语料的 2%）。**ICP 与 ProLong** 提出了一种极具巧思的构造法：利用 BM25 或稠密向量在语料库中构建近似最近邻图，通过贪心旅行商游走把**主题高度相关、共享实体或引用链的多篇中短文档**首尾串联成 64K–128K 序列（例如把同一历史事件的多篇维基词条、新闻追踪与论文综述拼在一条序列里）。不同于第 2 章必须用<a class="term-ref" href="/books/llm-data/glossary#intra_doc_masking" title="在打包多篇不相关文档时阻断跨文档互见的块对角掩码">块内注意力掩码</a>隔绝无关文档，语义聚类长序列正是为了刻意鼓励模型跨越段落边界建立隐式检索与跨文档综合推理能力！
3. **合成长程依赖任务（Synthetic Long-Dependency Data）**：即便读了很多长书，自然语言里大部分词的预测仍然高度依赖前 500 个 Token（局部短程相关性占主导），导致远距离注意力头得不到充分梯度训练。在退火末段混入 **3%–8%** 的合成长依赖样本（如跨十万字的多跳实体聚合、长文档全局大纲重构、跨 20 个代码文件的调用链追踪与变量溯源），能像“针灸”一样精准唤醒模型的全局检索注意力头（Retrieval Heads），把“大海捞针（NIAH）”与真实长文推理同步推向高分。

### 128K / 1M 扩窗阶段典型燃料混配参考表（如 200B 扩窗预算）

| 长窗燃料子集 | 推荐占比 $w_m$ | 目标序列长度分布 | 核心工程检验标准 |
| --- | --- | --- | --- |
| **原生长文档（书/代码仓/论文/年报）** | **30%–35%** | 32K–256K+ 原生连续 | 排除日志/灌水楼/大 JSON；按段抽检信息熵平稳 |
| **语义聚类拼接序列（ProLong / ICP）** | **20%–25%** | 64K–128K 主题链 | 同链内跨文档余弦相似度 $> 0.65$，刻意不加跨文档掩码 |
| **合成长程依赖与多跳聚合** | **5%–8%** | 64K–1M 精准跨距 | 答案跨度均匀覆盖全序列 $0\%\text{–}100\%$ 区间，杜绝“首尾偏置” |
| **高质短文档压舱石（带块内掩码）** | **32%–40%** | 4K–16K 打包隔离 | 防止 4K 短窗常识、MMLU 与数学精度出现退化回撤 |

::: tip 渐进式长窗课程 + “30% 短文压舱石”法则
从 8K 一步跳到 1M 不仅激活显存与序列并行通信开销骤增，而且容易引发注意力分布剧烈震荡。工业标准是分两到三阶梯渐进扩窗（如 **8K → 32K → 128K → 1M**），每阶段消耗 50B–200B tokens 并阶梯上调 RoPE 基频；更重要的是，**在长窗扩展期必须强制保留至少 30%–40% 的优质常规短文档（带严格块内掩码打包）**，否则模型在短文本常识、MMLU 与日常指令遵循上会出现明显的“长窗遗忘退化”。
:::

::: warning 退火期是数据污染风险最高的“雷区”
因为退火期最后 5% 数据对最终权重影响极大，只要这个阶段混进哪怕 0.1% 与公开评测集重叠的题库或合成变体，离线分数就会瞬间虚高 10+ pp！所有进入 Mid-training 退火池的数学、代码、合成问答与长文档数据，必须以最高严苛度重跑第 3 章的<a class="term-ref" href="/books/llm-data/glossary#decontamination" title="在语料入库或训练前主动识别并剔除与公开基准或密封评测集重叠样本的防火墙">三层去污防火墙</a>，并对每一份新增子集留存可追溯的 Micro-annealing 消融增益记录。
:::

至此，从源头解析、过滤去重、改写合成到退火扩窗的完整预训练“算法配方”已经全部摊开在桌面上了。但纸面上的配方要真正跑在 **100 TB 原始归档、15T–30T 净 Token、数千张 GPU 昼夜吞吐** 的工业集群上，立刻会撞上一连串硬核系统工程难题：该用 Parquet、Lance、WebDataset 还是 Megatron `.bin/.idx`？Datatrove、Ray Data、Spark 和 NeMo Curator 各自瓶颈在哪？如何保证千卡扩缩容不断片、确定性续训一帧不差？下一章，我们深入万亿 Token 分布式数据处理基建。
