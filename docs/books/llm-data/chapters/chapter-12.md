# 第 12 章 视觉-语言（VLM）基础数据：图文对、交错文档与密集重打标

<p class="chapter-summary">剖析网页图文对从 LAION 到 DataComp/DFN 的多级净化演进，拆解图文交错文档（OBELICS/Mint-1T）保留多图指代上下文的核心机理，给出 VLM 密集重打标（Dense Recaptioning）的结构化模式与千图成本账本，以及代码反向渲染 OCR/图表/蓝图/UI 工厂与动态分辨率（AnyRes）视觉 Token 核算。</p>

跨出纯文本世界、迈入多模态数据工程的第一步，几乎所有团队都会遭遇一场认知冲击：**网页图文数据的原始噪声水平比纯文本恶劣一个数量级**。在 CommonCrawl 抓取的原始图像里，超过一半的 `alt` 文本只是无意义的文件名（`IMG_4829.jpg`）、电商 SEO 关键词堆砌或完全文不对题的网站横幅；图像本身则充斥着模糊缩略图、全屏水印、死链占位符与纯文字广告。要想训出既能精准识图、又能吃透复杂 PDF 财务报表与高分 UI 截图的强 VLM，必须同时握稳“网页图文净化重打标”与“程序化高精度文档合成”两座引擎。

## 12.1 网页图文对的净化演进：从 LAION 到 DataComp 与 DFN

回顾开源视觉-语言预训练数据的三次代际跃迁，核心脉络正是**从“拼十亿级规模”彻底转向“拼多级过滤信噪比”**（详见[经典开源数据集档案](/books/llm-data/topics/dataset-archive)）：
- **LAION-400M / 5B 时代（粗筛扩容）**：证明了用 CLIP 余弦相似度做单一阈值截断即可规模化拉起海量图文对，但留存数据仍存在大量低分辨率图标、水印图、语义弱对齐与文本 SEO 噪声。
- **DataComp 时代（可控筛选基准）**：在固定 12.8B 候选池与固定计算预算下系统验证了数据过滤本身就是最大杠杆——叠加文本语言/长度规则、图像尺寸与长宽比限制、去重与多模型对齐集成后，仅取原始池的 10%–15% 即可全面碾压全量裸训。
- **DFN（Data Filtering Networks）时代（高质量小模型打分器）**：不再迷信公开预训练 CLIP 的固定偏置，而是先用极高质量精标图文对训出专用的高质量图文过滤网络（类似纯文本里的 FineWeb-Edu 分类器），再用 SigLIP / DFN 联合打分对百亿图文对做精准截断。

工业级网页图文过滤流水线按**算力由廉到贵**串接四道硬闸门，在最小化昂贵 GPU 算力开销的前提下收敛<a class="term-ref" href="/books/llm-data/glossary#yield_funnel" title="原始语料经过全流水线解析、过滤与去重后的端到端留存比例与损益账本">数据留存漏斗</a>：

| 过滤阶段 | 核心判断维度与常用阈值 | 计算开销 | 典型阶段留存率 | 重点清除的噪声形态 |
| --- | --- | --- | --- | --- |
| **1. 基础物理体检** | 短边 $\ge 224\text{ px}$、长宽比 $\in [1/3, 3]$、成功解码无损坏 | 极低（CPU） | ~72% | 导航小图标、分割线、长条广告 Banner、截断坏图 |
| **2. 视觉美学与污染拦截** | 美学评分 $> 4.5$、拉普拉斯清晰度、水印检测器、文字遮挡比、NSFW 与敏感人脸<a class="term-ref" href="/books/llm-data/glossary#pii_redaction" title="在文本、图像与音频中自动检测并脱敏个人身份信息的隐私保护管线">脱敏</a> | 低（轻量 CNN） | ~62% | 满屏图库水印、拍虚糊图、大面积促销弹窗遮挡图 |
| **3. 跨模态语义对齐** | CLIP / SigLIP 图文相似度 Top 30% + DFN 质量打分 | 中（批 GPU） | ~35% | 挂羊头卖狗肉的图文错配、文件名型死 Alt-text |
| **4. 感知哈希与语义去重** | 图像 pHash / DINOv2 向量 + 文本<a class="term-ref" href="/books/llm-data/glossary#semdedup" title="在向量聚类簇内剔除高度雷同样本以提升概念覆盖密度的方法">语义去重</a> | 中（分布式索引） | ~75% | 电商同款换背景刷屏、高频表情包与新闻通稿复刻 |

四级连乘后，端到端留存率 $\eta_{\text{yield}} \approx 0.72 \times 0.62 \times 0.35 \times 0.75 \approx \mathbf{11.7\%}$——看似残酷，但正是这种近 9:1 的狠心削减，才让单位视觉 Token 的有效信息密度提升数倍。

## 12.2 图文交错文档（Interleaved Data）：保住多图指代与长上下文

单图配一句话的 `(Image, Caption)` 数据虽然能把“物体长什么样”对齐到词向量空间，但存在致命局限：它无法教会模型**跨多张图做对比推理、理解“如图所示/上表第二列”的上下文指代，也无法支撑多轮带图对话与多模态上下文学习（In-context Learning）**。

以 **OBELICS** 与 **Mint-1T** 为代表的<strong><a class="term-ref" href="/books/llm-data/glossary#interleaved_data" title="保留原始网页或论文中文本段落与多张配图自然先后顺序的连续多模态序列">图文交错文档（Interleaved Image-Text Data）</a></strong>工程范式，直接从原始 WARC 网页 DOM 树、学术 PDF 版面与技术百科出发，提取完整的 `[段落1, <img1>, 段落2, <img2>, 段落3...]` 连续流。清洗交错文档有三条独有红线：
1. **DOM 节点保序与正文降噪**：剔除侧边栏广告、用户头像、社交分享图标与页脚徽章（防止打断正文语义流），仅保留与主体段落强关联的内容插图；同时设置健康图文密度窗口（如单文档至少 2 张有效图、每张图周边有效正文不少于 40 词且不超过 2,000 词），清除孤立图库画廊与近乎纯文本的伪交错页面。
2. **站内模板图全局摘除**：大量电商与博客站点会在不同文章的图文之间反复插入相同的“分隔装饰线”或“促销海报”；必须在域名/站点维度统计图像感知哈希频率，凡重复出现超阈值（如 $> 10$ 次）的一律全局剥离。
3. **跨文档块内注意力掩码**：与第 2 章纯文本打包铁律一致，将多篇短交错文档拼入同一条固定长窗口（如 32K）时，必须在文档边界严格阻断跨文档注意力互见，严防模型把上一篇菜谱的配图错认成下一篇电路图的说明。

### 图文交错文档入库硬性门槛（OBELICS / Mint-1T 工程口径）

| 清洗检查项 | 推荐入库阈值 | 过滤目标 |
| --- | --- | --- |
| **单篇有效图像数** | $2 \le N_{\text{img}} \le 30$ | 剔除单图新闻短讯与动辄数百张图的电商画廊页 |
| **图均正文密度** | $40 \le \text{词数}/\text{图} \le 2{,}000$ | 保持紧密的“图-文互指”上下文关联强度 |
| **站内高频模板图** | 同域名感知哈希出现次数 $\le 10$ | 剥离装饰分隔线、作者固定头像与站内广告横幅 |
| **图像物理可达与完好率** | 文档内链接成功解码率 $\ge 90\%$ | 避免缺失关键配图导致正文“如下图所示”变成悬空幻觉 |

## 12.3 密集重打标（Dense Recaptioning）工厂与千图成本账本

即便通过了 CLIP/SigLIP 过滤，真实网页 Alt-text 平均也只有 8–15 个词（如 `"红车停在街边"`），漏掉了画面里 90% 以上的空间方位、属性材质、文字标牌、人物动作与背景因果。于是，<strong><a class="term-ref" href="/books/llm-data/glossary#dense_recaptioning" title="用强 VLM 重新审视图像并生成覆盖主体、空间、文字与细节的高信息密度描述以替代噪声 Alt-text">密集重打标（Dense Recaptioning）</a></strong>成为现代 VLM（如 ShareGPT4V、PixMo、Qwen-VL、InternVL 体系）最核心的提纯引擎。

高质量重打标绝不是让 VLM 泛泛输出一段华丽散文，而是用结构化 Prompt 强制覆盖五大信息槽位：① **主体与细粒度属性**（数量、颜色、材质、姿态）；② **精确空间布局**（前景/中景/背景、相对左右上下方位）；③ **画面内可见文字原样抄录（In-image OCR）**；④ **动作与交互因果关系**；⑤ **图像体裁与拍摄视角**（摄影/插画/截图/显微图、俯拍/微距）。为防止重打标抹掉原图携带的世界专有实体（如特定地标、物种名或历史人物），最佳实践是采用**上下文感知重打标（Context-aware Recaptioning）**：将清洗后的原始 Alt-text 与周边标题作为参考线索附在 Prompt 中，由 VLM 核实画面证据后自然融合进密集描述。

**完整数值账本：1,000 万张精选图像的密集重打标批处理成本**。严格对齐全书统一基准口径（[核心公式与数据账本速查卡](/books/llm-data/toolkit/formulas-and-ledgers)），在离线 8×H100 集群（联动[《LLM 推理工程》](/books/llm-inference/)的连续批处理与系统提示前缀 KV 缓存复用）上运行 7B–32B 强 VLM，单图平均消耗 **500 输入 tokens** 与 **250 输出 tokens**：

| --- | --- | --- | --- | --- | --- |
| **高效 7B–11B VLM** | $\$0.12 / \$0.35$ per 1M | $\$0.148$ | $65\%$ | **$\$0.23$ / 千图** | $\$2{,}300$ |
| **旗舰 32B VLM（推荐主力）** | $\$0.20 / \$0.60$ per 1M | $\$0.250$ | $70\%$ | **$\$0.36$ / 千图** | $\$3{,}600$ |
| **超大 72B+ 教师 VLM** | $\$0.32 / \$0.95$ per 1M | $\$0.398$ | $74\%$ | **$\$0.54$ / 千图** | $\$5{,}400$ |

三档均精准落在教材基准 **$\$0.15\text{–}\$0.60$ / 千图**区间；仅需数千美元即可为千万级图像换上高信噪比“超级标注”。

## 12.4 高精度 OCR、统计图表、工程蓝图与 UI 截图合成工厂

对于企业落地最刚需的**复杂多栏 PDF、合并单元格财报、统计图表、工程蓝图与高分 UI 截图**，网页爬取加人工标注不仅成本高昂，还几乎必然存在抄录漏字与坐标漂移。工业界的降维打击方案是**代码反向渲染合成（Programmatic Rendering）**——先有 100% 精确的结构化源码真值，再批量光栅化出像素图像：

| 专项领域 | 上游源码生成引擎 | 同步导出的零错漏真值 | 必须叠加的真实退化增广 |
| --- | --- | --- | --- |
| **复杂文档与多栏表格** | LaTeX / HTML+CSS / Typst 模板随机化引擎 | 严格阅读顺序的 Markdown / HTML 表格 / LaTeX 公式 | 扫描微倾斜（$\pm 5^\circ$）、纸张折痕阴影、摩尔纹、低对比度灰底、JPEG 压缩伪影 |
| **统计图表与金融曲线** | Matplotlib / ECharts / Plotly / Vega-Lite 源码 | 精确底层 CSV 数据表、坐标轴刻度与多步数值问答对 | 变换字体族、双纵轴重叠、密集网格线、图例遮挡与主题色系扰动 |
| **工程蓝图与科学图示** | SVG / TikZ / Graphviz / CAD 矢量导出 | 节点连接拓扑 JSON、尺寸标注值与部件边界框 | 蓝底白线/白底黑线切换、局部缩放截图与线宽退化 |
| **网页与桌面 UI 截图** | 无头浏览器（Playwright）渲染真实网页与组件库 | 全部可交互元素的精确归一化边界框 `(x1, y1, x2, y2)` 与层级文本 | 多端分辨率（1080p/2K/移动端竖屏）、深浅色模式与不同缩放 DPI |

### 代码反向渲染工厂的三条防失真铁律

1. **统一结构化输出语法**：将合成表格与真实扫描件的标注统一为同一种规范（例如全量使用标准 HTML `<table>` 承载合并单元格 `rowspan`/`colspan`，或统一 LaTeX 数学定界符），严禁同一训练池里混杂三套冲突的表格格式。
2. **闭环校验坐标与视觉可见性**：无头浏览器导出 UI 或蓝图边界框时，必须用深度缓冲（z-index）或像素可见性检测剔除被弹窗遮挡、滚动到视口外或透明度为零的“幽灵元素”，避免教会模型凭空瞎猜坐标。
3. **控制合成与真实扫描的黄金比例**：在文档与图表桶中保持 **70%–80% 带退化增广的程序化合成图 + 20%–30% 清洗后真实扫描/翻拍文档**，同时覆盖无限结构多样性与真实物理成像噪声。

## 12.5 动态分辨率切片（AnyRes）与视觉 Token 预算账本

造出高分辨率文档与界面图后，如果视觉编码器仍把整张图粗暴压扁成固定 $336\times 336$ 正方形，密集小字与表格线会瞬间糊成马赛克。因此必须配套<strong><a class="term-ref" href="/books/llm-data/glossary#dynamic_resolution" title="按原图长宽比自适应切分为若干标准图块加一张全局缩略图以保住小字与坐标信息的多图块方案">动态分辨率切片（Dynamic Resolution / AnyRes）</a></strong>策略——按原图长宽比自适应切分为 $n_h \times n_w$ 个标准清晰图块外加 1 张全局缩略图（供模型把握整体版面）。套用全书统一的视觉 Token 账本（ViT Patch $p = 14$，$2\times 2$ 空间下采样池化 $s_{\text{pool}} = 2$）：

$$
T_{\text{img}}(H, W) \;=\; \left\lceil\frac{H}{p}\right\rceil \left\lceil\frac{W}{p}\right\rceil \cdot \frac{1}{s_{\text{pool}}^2} + T_{\text{meta}}
$$

| 典型图像形态 | 输入像素分辨率 | AnyRes 切片布局（基础块 $448^2$） | 视觉 Token 账 $T_{\text{img}}$ | 工程意义与序列打包注意 |
| --- | --- | --- | --- | --- |
| **常规自然场景图** | $448 \times 448$ | $1 \times 1$ 单块 | **256** tokens | 高吞吐、适合大规模预训练与常规图文对齐 |
| **高清截图 / 复杂图表** | $1120 \times 1120$ | 直接高分编码（或 $2\times 2$ + 缩略图） | **1,600**（或 **1,292**）tokens | 兼顾清晰刻度与合理显存，视觉推理主力口径 |
| **A4 密集多栏财报 PDF** | $1344 \times 1792$ | $3 \times 4$ 清晰块 + 1 全局缩略图 | **3,348** tokens | 保住 8pt 脚注小字；需按长短分桶打包防 Padding 浪费 |

**逐项算例拆解**：以 $1344 \times 1792$ 的 A4 财报页为例，先匹配最贴合 $3:4$ 比例的 $3 \times 4 = 12$ 个 $448 \times 448$ 高清图块，外加 1 张缩放到 $448 \times 448$ 的全局缩略图（共 13 块）。每块经 Patch $p=14$ 切分为 $32 \times 32 = 1{,}024$ patches，再经 $2\times 2$ 空间池化压缩为 $256$ tokens；加上行分隔与起止边界控制符 $T_{\text{meta}} = 20$，总计 $13 \times 256 + 20 = \mathbf{3{,}348}$ **tokens**。若训练批次内把这张 3,348-token 财报与 256-token 自然场景图随机混拼而不分桶，单步显存与通信将被长尾图拖垮——必须配合多模态序列打包与动态长度分桶。

::: tip 黄金配方原则：原始上下文与密集重打标必须“双轨混配”
切忌 100% 抛弃原始 Alt-text 而只喂纯 VLM 重打标描述，否则模型对世界实体名词（地标建筑、细分动植物种、品牌型号、专业仪器）的识别力会明显退化。工程上推荐将**干净原始 Alt-text（或 Context-aware 融合版）与纯视觉 Dense Recaptioning 按约 3:7 混合训练**，既拿到细粒度空间感知，又牢牢守住世界知识密度。
:::

::: warning 警惕合成文档数据的“域间隙（Domain Gap）”
如果 OCR 与图表数据 100% 来自干净白底的 LaTeX/Matplotlib 渲染图，模型在真实企业手机翻拍发票、倾斜盖章合同与低光投影仪照片上会瞬间断崖式掉点。必须把真实扫描件/翻拍件的弱监督清洗池（占 20%–30%）与带物理退化增广的合成数据混配，并严格统一两者的阅读顺序与合并单元格语法规范。
:::

攻克了静态图像、交错图文与高密文档后，多模态世界还有两块数据体积更大、时序耦合更紧的硬骨头正在前方——动态演进的视频流与毫秒级互动的全双工语音。下一章，我们将算清视频时空采样、双工语音对齐以及让无数多模态集群 GPU 利用率跌破 35% 的大二进制 I/O 账本。
