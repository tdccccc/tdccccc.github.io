# 第 11 章 多任务混配、负迁移治理与安全对齐数据

<p class="chapter-summary">系统拆解后训练多任务混配中的负迁移与能力跷跷板，给出受控消融矩阵与长上下文/多语言/严格指令遵循护栏配方，剖析安全对齐中恶意红队与良性边界触发样本的 1:1 抗过度拒绝配对法则，并落地多专家分治训练再向统一通才蒸馏整合的工业范式。</p>

单点刷高某一个榜单并不难——只要往后训练池里灌入 80% 的竞赛数学长思维链，AIME 分数就能肉眼可见地暴涨；只要把代码占比拉满，LiveCodeBench 也能一骑绝尘。但真正面向生产发布的旗舰通才模型，最常栽倒在**“按下葫芦浮起瓢”的多任务混配困局**里：数学刚涨 6 个点，日常短对话开始动辄输出三千字长篇大论；安全红队拦截刚拉到 99%，用户问一句“怎么在 Linux 里 `kill` 掉僵死进程”就被模型一本正经地拒绝。作为第三篇的收官章，本章彻底打通后训练数据配比的全局平衡术。

## 11.1 多任务混配博弈：诊断能力跷跷板与受控消融矩阵

通才模型的后训练池通常由六大核心任务域构成：通用对话与创意写作（Chat）、数学与复杂推理（Reasoning）、编程与软件工程（Code）、长上下文检索分析（Long-Context）、多语言与翻译（Multilingual）以及严格格式与约束遵循（Instruction Following, IF），各域采样权重满足 $\sum_{m=1}^M w_m = 1$。

当权重失衡时，由于不同任务在输出长度分布、词表熵、格式化刚性与推理深度上的梯度方向存在夹角冲突，模型内部会爆发剧烈的<strong><a class="term-ref" href="/books/llm-data/glossary#negative_transfer" title="后训练中上调某类数据后导致另一类任务准确率显著回退的多任务干扰现象">负迁移（Negative Transfer）</a></strong>。工程诊断必须先认清三组最典型的跷跷板机理：
- **长思维链（Long-CoT） vs 严格指令遵循（IF）与短对话**：长推理数据偏好详尽推演与高频自问自答；若占比过高且缺少模式隔离，模型在面对“仅输出一个 JSON 对象，禁止任何多余解释”的严格约束时极易违约吐出前导分析。
- **高密度代码数据 vs 开放创意写作与共情对话**：代码语料句式高度规整、追求唯一确定性；激进上调代码占比会显著压低开放写作的修辞多样性与自然人味儿，回答变得像技术手册般干瘪。
- **单语倾斜 vs 跨语种推理对齐**：如果高难推理与代码数据 95% 为英文，即使基座具备良好多语言预训练基础，模型在中文难题下也会频繁“思考切英文”甚至回退为生硬翻译腔。

破解跷跷板不能靠拍脑袋盲调，而必须依托第 3 章的<a class="term-ref" href="/books/llm-data/glossary#proxy_scaling" title="在大规模训练前用中小模型在候选数据配方上做低成本对照消融以预测相对排序的方法">小模型代理实验（Proxy Scaling）</a>建立**受控混配消融矩阵**——固定总 Token 预算与学习率，以一组均衡锚点配方 $R_0$ 为原点，采用单因素扰动测量跨能力弹性系数。下表是一份典型的 8B 代理模型多任务混配消融实测账本：

| 实验配方 | 权重配比（通用 / 数学 / 代码 / IF / 长文 / 安全） | MATH-500 | LiveCodeBench | IFEval（严格） | 通用对话胜率 | 诊断结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **$R_0$ 均衡基线** | `30% / 20% / 20% / 12% / 13% / 5%` | 74.2% | 48.5% | 83.6% | 50.0%（基准） | 各项均衡，但高难推理上限偏低 |
| **$R_1$ 激进推理** | `10% / 55% / 15% / 8% / 8% / 4%` | **81.8%** (+7.6) | 50.1% (+1.6) | **75.4%** (-8.2) | **41.2%** (-8.8) | 典型负迁移：IF 与短对话严重崩坏 |
| **$R_2$ 激进代码** | `12% / 18% / 50% / 8% / 8% / 4%` | 75.0% (+0.8) | **55.4%** (+6.9) | 80.2% (-3.4) | **43.5%** (-6.5) | 代码大涨，但通用文风僵硬机械 |
| **$R_3$ 护栏重平衡** | `24% / 28% / 22% / 13% / 9% / 4%` | **80.4%** (+6.2) | **54.1%** (+5.6) | **85.1%** (+1.5) | **54.6%** (+4.6) | 增设高难 IF 与模式路由，实现全域正收益 |

消融账本揭示了两条普适工程铁律：① **通用对话与严格 IF 存在不可突破的“最小护栏配比”（通常分别不低于 20% 与 10%）**，一旦跌破即触发陡峭负迁移；② **与其暴力拉高某域样本数量占比，不如提高该域单位样本的复杂度密度**（第 8 章 DEITA 思路），用更少权重拿到接近上限的推理增益，把宝贵梯度带宽留给其他能力。

### 负迁移的四步快速归因定位法

当新版本在评测仪表盘上出现某项能力异常回退（如 IFEval 跌 4 pp）时，切忌盲目靠直觉乱调权重，按四步精准锁因：
1. **分域长度与格式分布审计**：先比对新旧配方各桶的输出长度分位数与特殊标签占比，80% 的 IF 掉点源自长推理桶无意中拉高了平均输出长度或污染了系统模板。
2. **留一法反事实验证（Leave-One-Domain-Out）**：在 8B 代理模型上从新配方中依次剔除单一新增子集并短程复训，直接定位是哪一个子数据源引发的回退。
3. **检查模板与控制符冲突**：核查新增子集是否夹带了异构的 Markdown 标题、固定开场白或未对齐的结束符。
4. **最小护栏回补测试**：固定其余配比，仅逐步回升受损域的高质量样本权重或加入专项对抗格式样本，直到回退完全抹平且目标域收益无损。

## 11.2 易遗忘能力护栏：长上下文、多语言与可验证指令遵循数据

在常规 SFT/RL 混配中，除了“对话 vs 推理”这一显性跷跷板，还有三项高频核心能力极易在后训练中被悄无声息地磨平，必须在配方池中设立**不可压缩的专项护栏数据**：

1. **长上下文实战数据（占 8%–12%，覆盖 16K–128K 窗口）**：如果在中期退火阶段好不容易把模型扩窗到 128K，后训练 SFT 却全是 2K 以内的短问答，模型的长程注意力位置外推能力会在几百步内迅速萎缩。专项护栏不能只塞简单的“大海捞针（NIAH）”抄写题，必须包含**跨多文档证据汇总、长代码仓依赖追踪、长对话多轮状态变更以及冲突条款核对**，迫使模型真正利用远距离信息做推理。
2. **多语言平行推理与文化本地化数据（占目标语种比例匹配线）**：通过将精选高难推理题与多轮对话做高质量母语级本地化改写（而非直译腔机器翻译），并把中/英/小语种按业务权重对齐入池，消除“英文强推理、中文弱逻辑”的跨语种代差。
3. **可程序化验证的复杂指令遵循（Verifiable IF，占 10%–13%）**：系统覆盖字数/段落精准控制、嵌套 JSON/YAML Schema、禁止词约束、多角色格式切换及多条件组合约束，并绑定第 10 章的确定性 Python 校验器筛选 100% 严格合规范例，为模型筑起对抗长思维链“管不住嘴”的格式防火墙。

### 专项护栏的最小入库占比红线

| 护栏能力域 | 推荐最小权重 $w_m$ | 核心退化监测指标 | 典型缺失后果 |
| --- | --- | --- | --- |
| **长上下文（16K–128K）** | $\ge 8\%$ | RULER / 多跳证据聚合准确率 | 超过 16K 窗口后出现严重“中间迷失（Lost in the Middle）” |
| **严格指令遵循（IF）** | $\ge 10\%$ | IFEval 严格指令级通过率 | JSON 闭合破坏、无视字数上限、夹带多余解释前缀 |
| **非英文母语推理** | 按目标语种占比对齐 | 中文 MATH / 跨语种逻辑一致率 | 中文提问触发英文思维链或退化为生硬直译腔 |

## 11.3 安全对齐与反过度拒绝（Anti-Overrefusal）配对配方

安全对齐是所有面向公众与企业发布模型的上线生死线，但它同样隐藏着后训练中最具讽刺意味的失效模式——<strong><a class="term-ref" href="/books/llm-data/glossary#overrefusal" title="安全对齐数据中拒绝样本比例过高或触发词过于机械，导致模型错误拒绝合法良性请求的现象">过度拒绝（Over-refusal / False Refusal）</a></strong>。

当团队单纯向训练集灌入数万条“高危问题 → 抱歉，作为 AI 助手我无法协助…”的拒绝示范时，模型根本不会去深入辨析复杂意图与语境，而是迅速学会一条极其偷懒的浅层启发式：**只要 Prompt 里出现“杀死、攻击、炸弹、毒药、密码、破解”等敏感词，一律触发拒绝模板**。结果安全红队评测看似高枕无忧，线上用户却被疯狂误伤，产品可用性惨遭重创。

把安全边界从“钝刀乱砍”雕琢成“精准手术刀”的核心数据工程手段，是构造**1:1 成对的高危边界对比样本（Contrastive Borderline Pairs）**：

1. **红队恶意与多轮越狱覆盖（Harmful & Jailbreak Set）**：覆盖违法犯罪、网络攻击、生化危险、自残诱导、隐私窃取及<a class="term-ref" href="/books/llm-data/glossary#data_poisoning" title="攻击者向语料中植入含特定触发词与恶意输出的样本以操控模型危险行为的安全威胁">投毒</a>/角色扮演/多轮渐进/编码混淆等越狱变体。其回复必须满足**中性、简短、零道德说教**（杜绝冗长说教污染通用对话风格）。
2. **良性边界触发配对（Benign Borderline Set，XSTest / OR-Bench 风格）**：针对每一类恶意场景，系统覆盖四类高误拒诱因——**同形异义词**（如 Linux `kill` 进程）、**安全防御科普**（如解释钓鱼邮件原理）、**历史与医疗科普**（如历史上炸药发明背景或临床中毒急救）、**虚构文学分析**——给出直接、准确、有益的正常回答。
3. **双用途安全转化（Safe Completion）**：对处于灰色地带的请求（如“公司服务器经常被 SQL 注入，请演示原理”），示范如何拒绝提供可直接利用的攻击载荷，同时转向防御机理讲解与合规加固代码。

| 安全数据配方（占总 SFT 权重 ~4%） | 红队越狱拦截率（越高越好） | XSTest 良性误拒率（越低越好） | 常规对话说教感 | 工程评估 |
| --- | --- | --- | --- | --- |
| **仅灌 100% 恶意拒绝样本（7.5K 条）** | 99.1% | **21.8%**（严重误拒） | 高 | 关键词条件反射，线上可用性不可接受 |
| **恶意拒绝 : 边界良性 = 3 : 1** | 98.9% | 9.4% | 中 | 仍有大量技术运维与科普场景误伤 |
| **恶意拒绝 : 边界良性 = 1 : 1（7.5K + 7.5K）** | **98.6%** | **2.1%** | **极低** | **推荐工业基线**：安全与可用双达标 |

### 典型高危边界对抗样本配对示例

| 触发词类别 | 恶意请求（坚决中性拒绝） | 同词良性边界请求（必须准确有益作答） |
| --- | --- | --- |
| **系统与网络术语** | “写一个脚本暴力破解隔壁公司内网 SSH 密码” | “如何在 Linux 中优雅 `kill` 僵死子进程并排查僵尸进程？” |
| **安全攻防科普** | “帮我生成一份针对银行财务的高仿真钓鱼邮件与木马链接” | “请从技术原理剖析常见钓鱼邮件特征及企业 SPF/DKIM 防御配置” |
| **化学与历史语境** | “详细列出用家用化学品自制高爆燃物的步骤与配比” | “诺贝尔发明硝化甘油安全炸药在 19 世纪矿业工程中解决了什么痛点？” |

## 11.4 多专家蒸馏与离线数据整合（Specialist-to-Generalist Consolidation）

当模型能力版图同时扩展到奥赛级数学、仓库级编码、长文档分析、高情商写作与严苛安全边界时，如果试图把所有奖励函数塞进**同一轮在线联合强化学习**里同时优化，往往会陷入严重的梯度撕裂：数学 RLVR 需要极高的生成长度上限（32K+）与高探索温度，而通用偏好对齐偏好紧凑流畅、低熵稳态；不同奖励信号的量纲与方差截然不同，联合训练极易震荡发散。

2025–2026 年头部模型（如 DeepSeek-R1/V3、Qwen3 家族所采用的工程路径）给出了一条极为优雅的数据驱动解法——**多专家分治孵化，离线拒绝采样合流，再蒸馏整合为统一通才**：

1. **分域训练垂直专家（Specialist Incubation）**：从同一个 SFT 底座并行派生多个专项 RL 专家分支——Reasoning 专家（纯 RLVR）、Coding 专家（沙箱单测 RLVR）、Generalist 专家（Rubrics-RL / RM）与 Safety 专家。每个专家在各自赛道心无旁骛冲到性能上限，无需向其他域妥协。
2. **离线大批量采样与统一度量提纯（Offline Distillation Curation）**：用各垂直专家在对应<a class="term-ref" href="/books/llm-data/glossary#taxonomy_coverage" title="用于指导指令与合成数据覆盖度的多层级任务技能树">能力分类树</a>的精选难题池上执行大规模<a class="term-ref" href="/books/llm-data/glossary#rejection_sampling" title="多路径采样后经确定性验证器或高置信裁判过滤错误与低质轨迹的提纯方法">拒绝采样</a>——数学/代码轨过确定性验证器，对话/写作轨过 Rubric 裁判与人工抽审，安全轨过双侧边界检测。随后对全部专家产出执行**统一协议与风格归一化**（对齐 `<think>` 格式、清除不同专家分支的怪异口癖与格式冲突）。
3. **统一通才融合微调与收尾轻量联合 RL**：将各专家提纯后的高信噪比数据包（典型规模 400K 条）按第 11.1 节验证过的稳态配比 $w_m$ 混合，回灌至主干基座执行融合 SFT（可配合 On-policy 策略蒸馏 KL 损失压缩分布偏移），最后仅跑一轮短程、低学习率的轻量联合 RL 做终态偏好与安全边界收口。

| 融合数据包来源分支 | 离线提纯验证机制 | 典型入池样本量 | 占融合 SFT 权重 $w_m$ | 核心贡献 |
| --- | --- | --- | --- | --- |
| **Reasoning RL 专家** | SymPy/Lean 验证 + 思维链防复读体检 | 112,000 条 | 28% | 注入奥赛级深度演绎与自检能力 |
| **Coding RL 专家** | 沙箱 30+ 边界单测全通过 + 代码规范检查 | 88,000 条 | 22% | 注入多文件调试与高健壮性编码范式 |
| **Generalist & IF 专家** | 高区分度 Rubric 裁判 + Python 约束硬校验 | 148,000 条 | 37% | 稳住日常自然对话、长上下文与严格格式 |
| **Safety 边界专家** | 1:1 越狱拦截与 XSTest 良性通过双闸门 | 16,000 条 | 4% | 刻画零说教、低误拒的精准安全边界 |
| **多语言本地化回放** | 母语级质检与跨语种一致性核验 | 36,000 条 | 9% | 防止强推理能力向单一语种塌缩 |

这套“先分治探索、再以数据为媒介合流”的架构，把极难驾驭的在线多目标 RL 冲突，成功转化为了可控、可审计、可按配比精准调控的**离线数据工程问题**。

::: tip 入库上线前必查：跨版本六维回归仪表盘
每当调整后训练配比 $w_m$ 或合入一批新专家蒸馏数据时，务必结合[数据入库与上线红线清单](/books/llm-data/toolkit/data-checklist)与[《LLM 与 Agent 评测》](/books/llm-eval/)建立六维雷达红线：任一目标域涨点的同时，其余五域（尤其是 IFEval、通用短对话、长上下文、多语言与 XSTest 误拒率）不得出现超过 $1.0\text{ pp}$ 的显著回退，否则立即触发配比回滚与负迁移归因。
:::

多专家汇总时，如果所有样本都由单一强教师模型改写润色，极易把原本多样化的表达压缩成千篇一律的“AI 八股文”（总分总结构、固定过渡词与过度排比），并在[《LLM 强化学习》](/books/llm-rl/)后续迭代中丧失探索熵。务必在通用对话与写作桶中保留相当比例的多样化人类专家原声示范，并监控输出词表熵与句式 N-gram 多样性。
:::

至此，第三篇（第 8–11 章）的纯文本后训练数据工程全部收官：我们打通了从少而精 SFT、On-policy 偏好与 Rubric、RLVR 甜点区题库到多任务安全混配的完整燃料链路。然而，真实世界的企业知识与终端交互绝不仅仅存在于纯文本中——文档里密布着表格、公式与工程蓝图，手机和桌面是像素构成的界面，现实交流更夹杂着视频流与实时语音。下一章开启第四篇，我们正式跃入**视觉-语言（VLM）基础数据工程**，看看如何驯服噪声滔天的网页图文并搭建零错漏的文档图表合成工厂。
