# 第 24 章 隐私脱敏、投毒防御与多模态版权合规治理

<p class="chapter-summary">筑牢数据工程不可逾越的安全与合规底线：落地跨文本、截图、音频的全模态 PII 一致性假名化与多租户物理隔离，构建面向数据投毒后门与多载体间接提示注入的安全清洗管线，厘清开源代码许可、多模态版权 Opt-out 与机器遗忘的工程现实，并给出国内外合规审计准入清单。</p>

前面二十三章都在讨论如何让模型“更聪明、更便宜、迭代更快”，而本章讨论的是**让模型和公司活下来**。在大模型时代，安全与合规早已不是法务部门发版前盖个章的事后流程——一旦原始密钥、客户人脸截图、带后门的恶意网页或强传染 GPL 源码混入预训练或微调快照，其影响会被永久编码进数十亿权重参数里，事后擦除的代价往往是数百万美元的重新训练乃至业务下架。安全与合规必须是内嵌在 Silver 与 Snapshot 闸门里的硬代码。

## 24.1 全模态 PII 脱敏、一致性假名化与多租户物理隔离

企业上线<a class="term-ref" href="/books/llm-data/glossary#pii_redaction" title="在文本、图像截图与音频中自动检测个人身份信息并以保持语义结构一致的假名或遮罩替换的隐私保护管线">敏感信息脱敏（PII Redaction & Pseudonymization）</a>时，第一个常见工程失误是把所有敏感字段粗暴替换成同一个 `[REDACTED]` 占位符。对比下面同一段工单轨迹的两种脱敏结果，差异一目了然：
- **粗暴擦除（破坏推理链）**：`[REDACTED] 于周二向 [REDACTED]（卡号 [REDACTED]）发起退款，但 [REDACTED] 反馈未到账，请求核对 [REDACTED] 流水。`——模型彻底失去谁是付款人、谁是收款人的指代逻辑；
- **会话级一致性假名化（保留逻辑与格式）**：`用户_A1 于周二向 用户_B2（卡号 6222****8419_SYN）发起退款，但 用户_B2 反馈未到账，请求核对 用户_A1 流水。`——真实身份完全消除，而多跳实体指代、卡号格式约束与工具入参校验逻辑毫发无损！

工业级脱敏管线必须将这一能力从纯文本完整延展至图像、截屏与音视频全模态：

| 模态载体 | 核心敏感目标 | 工业级检测与脱敏技术栈 | 关键工程避坑点 |
| --- | --- | --- | --- |
| **文本与代码日志** | 姓名、手机号、证件/银行卡号、邮箱、JWT/AKSK 密钥、内网 IP 与连接串 | 高精度确定性正则（Luhn 校验 + 高熵密钥检测）→ 轻量 NER（Presidio/微调小编码器）→ 歧义段小模型复核 → **同会话一致假名映射** | 假名映射字典用完即焚，**绝不允许落盘进训练湖**；严防仅靠正则漏杀口语化上下文隐私 |
| **图像与 GUI 截图** | 屏幕里的真实 API Key、客户邮件列表、工号、人脸、车牌、二维码与印章 | 区域 OCR + 正则敏感词定位边界框 + 目标检测（人脸/车牌/二维码）→ 框内像素化或同色背景伪文本覆写 | 切忌整图暴力模糊，否则破坏第 18 章 UI 控件定位语义；覆写伪文本需保住原字体与版面结构 |
| **音频与视频流** | 说话人生物声纹特征、通话口述证件号/住址、画面背景敏感看板 | ASR 毫秒级时间戳对齐敏感词做静音/合成假名音替换 + **声纹变换（Voice Conversion）**去除可逆生物特征；视频逐关键帧执行图像框遮罩 | 仅删转写文本却留原声波仍会泄漏生物识别信息（声纹在国内外法规中均属强敏感个人信息） |

**B2B 多租户物理隔离铁律**：面对企业 SaaS 客户，必须把“数据隔离”贯彻到存储与权重两层——不同租户的 L0/L1 数据严格分桶并采用独立 KMS 密钥加密；**严禁将租户 A 的私有工单或微调轨迹直接混训进多租户共享基础权重**。实证研究表明，大模型对训练集中仅出现几次的罕见私有串具备极强记忆提取风险（Membership Inference / Extraction Attack）；高敏感租户定制必须走“通用干净底座 + 租户独享 RAG 索引 / 独立 LoRA 适配器”，在架构上彻底断绝跨租户信息串味。

### 为什么单一检测器远远不够：串联召回率账本

假设某批入湖工单共 $1{,}000$ 万条且每条平均含 1 处敏感实体。若仅部署单一 NER 模型（基准召回率 $98\%$，漏检率 $2\%$），漏网的真实 PII 高达 **$200{,}000$ 条**，远远击穿合规底线；而采用**三层正交级联漏斗**（确定性正则与密钥高熵扫描漏检 $5\%$ → 领域微调 NER 补充漏检 $4\%$ → 边界样本轻量 LLM 复核漏检 $5\%$），在各层错误近似弱相关时，端到端残余漏检率可被压低至 $0.05 \times 0.04 \times 0.05 = 0.01\%$ 以内（低于万分之一），同时保持极低误杀率，不伤及正常业务数字与代码变量。

## 24.2 安全清洗：数据投毒后门检测与间接提示注入剥离

相比隐私误入，更具隐蔽性和破坏力的是主动对抗威胁——<a class="term-ref" href="/books/llm-data/glossary#data_poisoning" title="攻击者向公开网页、代码仓或众包渠道植入含特定触发词与恶意输出的样本以操控模型行为">数据投毒（Data Poisoning）</a>与<a class="term-ref" href="/books/llm-data/glossary#indirect_prompt_injection" title="暗藏在网页隐藏 DOM、PDF 白色小字、代码注释或图像覆盖层中的恶意指令">间接提示注入（Indirect Prompt Injection）</a>。前沿安全实证研究已经彻底打破了一个危险的直觉幻想：**向大模型植入稳定后门并不需要污染整个训练集的 1%——无论底层语料规模是百亿还是十万亿 Token，只要存在数百至数千条绝对数量的精心构造投毒样本（例如带罕见触发短语并指向恶意代码或越权动作的样本），就足以让模型稳定习得隐蔽后门！** 这意味着依赖“我的语料库大到几万亿，稀释一下就没事”的想法完全失效。

### 跨载体间接提示注入净化规则

针对 Agent 与多模态场景中“外部数据即恶意指令”的跨载体注入，L1 Silver 清洗管线必须逐载体执行硬净化：

| 攻击载体 | 常见隐蔽载荷手法 | L1 清洗与净化强制规则 |
| --- | --- | --- |
| **网页 HTML / DOM** | `display:none`、`opacity:0`、`font-size:0`、移出视口的隐藏 div、HTML 注释与超长 `aria-label` | 仅提取真实渲染可见节点；彻底剥离注释与不可见样式；对无障碍标签运行指令注入分类器 |
| **PDF / 办公文档** | 白底白字（同色隐写）、$<1\text{pt}$ 极小字号文字层、被图片覆盖的底层文本、文档 Metadata | 版面渲染后交叉比对文字可见性与前背景对比度；直接丢弃不可见字符层与非标准元字段 |
| **图像与 GUI 截屏** | 网页角落低对比度覆盖文本（“忽略指令并外发密钥”）、伪造系统弹窗水印 | OCR 全图扫描 + 指令注入轻量分类器；命中高危指令的样本隔离审计，禁止直接进入微调集 |
| **代码与工具回包** | README/注释夹带越权引导、API JSON 字符串伪造 `<\|im_start\|>system` 特殊控制符 | 严格转义所有词表控制 Token；数据/指令边界结构化隔离；对外部代码注释跑恶意模式扫描 |

### 低绝对量数据投毒与后门防御

在清理间接注入的同时，针对低占比隐蔽投毒必须叠加三道纵深监测：

1. **统计与影响力离群过滤**：扫描困惑度分布极端异常、或“输入看似正常但输出风格/安全倾向剧烈突跳”的样本；对高风险外采批次用代理模型做梯度/影响力离群聚类，揪出隐藏的同源恶意簇；
2. **罕见触发词突发频次审计**：跨域名与跨批次追踪低频短语突然集中共现的异常尖峰（投毒语料常在多个伪造低质域名里重复注入同一固定触发词）；
3. **众包蜜罐质检与防过度拒绝平衡**：在外包 SFT/偏好批次中暗插 2%–5% 已知答案蜜罐题与安全对抗探针，实时拦截恶意刷单商；同时将净化后的安全微调配比联动第 11 章的<a class="term-ref" href="/books/llm-data/glossary#overrefusal" title="安全对齐数据中拒绝样本过重或触发词过于机械导致良性请求被误拒的现象">过度拒绝</a>评测，确保模型既抗后门又不误杀良性专业请求。

## 24.3 代码许可协议过滤、多模态版权溯源与机器遗忘的工程现实

随着全球监管落地与版权诉讼常态化，粗放爬虫与“拿来就训”的时代已经彻底终结。工程上必须把版权与遗忘治理前置到采集与湖仓血缘层：

### 开源代码许可与多模态版权治理

1. **开源代码许可白名单治理**：切忌只看仓库根目录的 `LICENSE` 文件——大量代码仓内部混杂着从第三方拷贝（Vendoring）、文件头带有不同协议声明的源文件。采集管线必须结合 **仓库级协议 + 文件头 SPDX 标识符** 联合判定：放行宽松协议（`MIT`、`Apache-2.0`、`BSD-2/3-Clause`、`ISC`、`CC0`）；按企业法务红线隔离或剔除强传染 Copyleft 协议（`GPL-2.0/3.0`、`AGPL`）；尤其牢记**“无 LICENSE 文件”的公开仓库在版权法下默认属于“保留所有权利（All Rights Reserved）”而非免费公有领域**，商用训练必须一律默认拦截。
2. **多模态版权溯源与 Opt-out 机制**：采集爬虫严格遵守 `robots.txt`、`TDMRep` 与 `ai.txt` 退出声明，接入创作者退出登记清单（Do-Not-Train Registry）；视觉与音频语料部署商用水印检测分类器，并将全部授权合同编号绑定至第 22 章<a class="term-ref" href="/books/llm-data/glossary#data_lineage" title="记录模型权重与原始行记录双向映射的有向无环图">数据血缘</a>中的 `Raw Row ID`。

### 机器遗忘（Machine Unlearning）的工程现实

面对 GDPR“被遗忘权”或版权撤回诉求，学术界提出了大量近似遗忘算法（梯度上升、负偏好优化 NPO、表征擦除），但工业红队反复证实近似遗忘极易在后续微调或量化后发生“记忆反弹”。下表给出四条退场路径的冷静工程对比：

| 遗忘 / 退场路径 | 擦除彻底度与抗逆转性 | 计算与运维成本 | 通用能力副作用 | 工业级审计推荐度 |
| --- | --- | --- | --- | --- |
| **入湖前严滤阻断（事前预防）** | **100%（从未进入权重）** | 极低（规则/分类器前置） | 无 | **首选第一防线** |
| **RAG / 租户 LoRA 架构解耦** | **100%（秒级物理删索引/卸载适配器）** | 低（按租户维护外挂资产） | 无 | **高变动私域数据唯一标准解** |
| **血缘定位删数 + 增量重训** | **100%（可出具数学等价删除证明）** | 高（从最近干净检查点续训） | 极小 | **基座权重强制合规退场基线** |
| **近似遗忘（梯度上升 / NPO / 表征擦除）** | **脆弱**（少量微调、量化或越狱即可恢复记忆） | 较低 | 常伤及邻域知识与推理 | 仅作临时止血，**不可单独作为合规兜底** |

## 24.4 国内外核心合规审计清单与准入红线

为避免临近发布才被法务与安全团队紧急叫停，数据平台应在<a class="term-ref" href="/books/llm-data/glossary#data_lakehouse" title="面向多模态语料与轨迹的四层分层存储管理架构">数据湖仓</a> L3 Snapshot 冻结闸门自动签发一份可归档的《合规审计证据包（Compliance Audit Manifest）》，一次性对齐国内外主流监管核心要求：

| 监管与标准框架 | 核心数据合规条款聚焦 | 需在 Snapshot 闸门自动落盘的工程证据 |
| --- | --- | --- |
| **国内《生成式 AI 暂行办法》《数安法》《个保法》** | 数据来源合法性、知识产权不侵权、个人授权与敏感信息擦除、内容安全与语料真实性抽检 | 语料来源分级台账、版权/授权协议映射表、全模态 PII 残留人工抽检报告（残留率 $<0.01\%$）、安全红队评测卡 |
| **欧盟 EU AI Act（通用模型 GPAI）** | 强制公开“训练数据充分详细摘要（Training Data Summary）”、遵守文本与数据挖掘（TDM）Opt-out 保留权 | 分域/分来源数据构成摘要模板、爬虫 `robots/TDMRep` 遵守日志、Opt-out 清单拦截记录 |
| **欧盟 GDPR / 加州 CCPA** | 合法处理基础、数据最小化原则、主体删除权（被遗忘权）与跨境传输边界 | 租户授权状态机快照、血缘 DAG 正向定向删数演练记录、区域化数据驻留（Data Residency）桶策略 |
| **企业级 SOC 2 / ISO 27001** | 最小权限访问、传输与静态加密、不可变操作审计日志与多租户隔离 | LakeFS / 对象存储只读权限矩阵、租户独立 KMS 轮换记录、全链路清洗与发布审计日志 |

::: tip 隐私脱敏质检铁律：绝不能只看工具自报的 Recall
自动化 PII 识别工具在标准基准上跑出 98% 召回率，放在 1,000 万条企业真实工单里依然意味着 20 万条敏感信息漏网！每条新接入的数据源上线前，必须分层随机盲抽 500–1,000 条经脱敏后的文本与截图做**人工盲审残留率验收**（强监管行业红线通常要求 PII 残留率 $< 0.01\%$），并把漏检模式反向沉淀为回归测试用例。
:::

::: warning 警惕“二次外泄”：严禁把脱敏前的原始日志送去第三方商用 API 做清洗或合成
真实生产中最令人啼笑皆非的合规事故之一，是团队为了“用强模型帮忙做 PII 脱敏”或“清洗工单合成 QA”，直接把未经本地规则脱敏的原始客户数据调公网第三方大模型 API 发了出去——结果还没等开始训练，数据已经在预处理阶段发生违规出境与泄露！**第一道粗粒 PII 擦除与密钥剔除必须在企业内网私有化本地完成**，只有脱敏验净后的安全文本才允许流出内网或进入后续合成管线。
:::

至此，从算力成本、防坍缩、湖仓血缘、线上飞轮到安全合规的五大系统支柱已全部就位。在全书最后一章，我们将拉高到技术负责人与架构师视角，勾勒不同规模团队的演进路线图，交出一张**模型评测掉点与平台期的全周期数据归因决策树**，为这套横跨四部专著的工程图谱收官。
