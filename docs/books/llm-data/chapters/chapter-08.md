# 第 8 章 SFT 指令数据构造：多样性、复杂度与长思维链冷启动

<p class="chapter-summary">厘清监督微调（SFT）在后训练栈中的真实职责，定量拆解为何 5 万条高信噪比指令胜过 200 万条噪声指令，系统落地能力分类树（Taxonomy）、Evol-Instruct/Magpie/Persona 合成、DEITA 复杂度×质量二维筛选与语义去重，并给出 Long-CoT 冷启动拒绝采样、防过度思考清洗与多轮打包掩码的完整工程规范。</p>

从本篇起，我们正式迈入大模型与 Agent 的后训练燃料供应工程。无数团队在第一次做后训练时都会踩进同一个昂贵的误区：**把预训练的“越多越好”惯性照搬到 SFT，从开源社区拼凑两三百万条风格杂乱、答案平庸甚至充满幻觉的指令一股脑灌进基座模型**。结果往往事与愿违——模型虽然学会了客套话，但数学和代码准确率不升反降，稍遇复杂约束便格式崩坏。本章从第一性原理出发，先把 SFT 的真实边界立清楚，再拆解从 200 万原始池淘出 5 万高信噪比样本与 Long-CoT 冷启动包的系统方法。

## 8.1 SFT 的真实职责：为什么 5 万条高信噪比样本胜过 200 万条噪声指令

正如[《LLM 强化学习》第 1 章](/books/llm-rl/chapters/chapter-01)从策略优化视角指出的那样：大模型的绝大多数世界知识与底层语言能力，早已在万亿级预训练和中期退火阶段写入权重。SFT 的本质不是在极小 Token 预算内强行灌输全新百科知识，而是承担三项精确职责：

1. **交互格式与角色对齐（Format & Protocol Alignment）**：教会基座模型理解多轮对话模板（Chat Template）、系统指令优先级、结构化输出（JSON/Markdown/代码块）以及思考与回答分离边界。
2. **输出风格与推理范式激活（Style & Paradigm Activation）**：将预训练里沉睡的演绎、验证与分步规划能力，唤醒为稳定可控的推理风格与回答结构（例如先澄清假设、再分步推导、最后核验边界）。
3. **强化学习的冷启动底座（RL Cold-start Anchor）**：在进入第 10 章的 RLVR 之前，赋予策略一个“可读、可解析、具备基本反思习惯”的初始分布 $\pi_{\text{SFT}}$，避免纯零样本基座在强化学习初期陷入语言混杂或死循环。

从全书统一的<a class="term-ref" href="/books/llm-data/glossary#effective_tokens" title="扣除重复衰减、质量噪声、数据污染与合成坍缩折损后，真正转化为泛化收益的折算 Token 量">有效数据量</a>账本审视，SFT 样本数通常仅有 $10^4\text{–}10^5$ 级，总 Token 量（数千万至数亿）不及预训练的万分之一，但单步学习率敏感度高、单位样本对条件输出分布的塑形权重高出数个数量级。一旦数据集中混入大量平庸、敷衍、自相矛盾或带幻觉的回复，交叉熵梯度就会迫使模型**强行拉高错误断言与套话模板的似然**，稀释高难指令的信噪比（SNR）。更致命的是，强行灌入超出基座预训练记忆边界的冷门事实问答，还会直接教会模型“遇未知即编造”的幻觉习惯。

下面是一份典型的 200 万开源混拼指令池提纯至 5 万高信噪比金标的端到端漏斗账本（与 [经典开源数据集档案](/books/llm-data/topics/dataset-archive) 中的 Tulu-3 / OpenThoughts 思路一脉相承）：

| 清洗阶段 | 留存样本量 | 阶段留存率 $\eta_i$ | 核心操作与剔除对象 | 对下游能力影响 |
| --- | --- | --- | --- | --- |
| **0. 原始混拼池** | $2{,}000{,}000$ | 100.0% | 聚合多源开源指令、合成对话与历史业务问答 | 基线（含大量重复模板、机翻病句与截断回复） |
| **1. 硬规则与去污** | $1{,}100{,}000$ | 55.0% | 精确/MinHash 去重、空答/截断清洗、编码修复与基准<a class="term-ref" href="/books/llm-data/glossary#decontamination" title="在语料入库或训练前主动识别并剔除与公开基准或密封评测集重叠的样本">去污</a> | 消除格式错乱与虚假刷榜风险 |
| **2. 分类树平衡 + 语义去重** | $330{,}000$ | 30.0% | 按能力树限流“泛泛改写/闲聊”，簇内<a class="term-ref" href="/books/llm-data/glossary#semdedup" title="将样本编码为稠密向量，在聚类簇内剔除措辞不同但语义高度雷同样本的方法">语义去重（SemDeDup）</a>（$\tau_{\text{cos}}=0.88$） | 压缩同质化重复，释放稀缺高难能力占比 |
| **3. DEITA 二维打分精选** | $60{,}000$ | 18.2% | 联合评估复杂度 $C$ × 质量 $Q$，截取帕累托高分前沿 | 剔除“高难但幻觉”的伪难题与低信息水题 |
| **4. 推理体检与人工抽审** | **$50{,}000$** | 83.3% | 验证数学/代码答案、清除思维链复读与过度思考、1% 抽检 | 端到端 $\eta_{\text{yield}} = 2.5\%$，训练耗时降 $40\times$，综合基准反升 4–8 pp |

## 8.2 多样性工程：能力分类树（Taxonomy）与三类主流指令合成范式

如果只凭单一质量分截断，最终留下来的 5 万条样本往往会严重偏科——比如 70% 都挤在长篇写作与算法编程题里，而结构化抽取、多轮纠错、表格核对与边界拒答几乎绝迹。解决偏科的第一道工程底座是构建可量化的<strong><a class="term-ref" href="/books/llm-data/glossary#taxonomy_coverage" title="用于指导 SFT 与合成数据覆盖度的多层级任务与领域技能树">能力分类树（Taxonomy Coverage）</a></strong>：通常设计三层结构——一级能力域 8–12 个（推理、编程、信息抽取、创意写作、多轮对话、翻译、安全边界等）、二级子任务 60–100 个、三级细粒度场景与约束标签 500+ 个。

工程上使用 InsTag 或微调轻量标签分类器给全量样本打上多标签集合 $\mathcal{T}_i$，并按叶节点 $k$ 计算覆盖配额缺口 $\Delta n_k = \max(0, N_k^{\text{target}} - n_k)$ 与标签分布熵 $H_{\text{tag}}$。当发现关键叶节点（如“多条件冲突检测”“复杂 SQL 性能调优”“金融年报口径核对”）存在明显盲区时，采用三类主流指令合成范式做定向补盲：

| 合成范式 | 核心机理与代表工作 | 核心优势 | 典型隐患与防漂移对策 |
| --- | --- | --- | --- |
| **演化升维（Evol-Instruct）** | 对种子指令执行深度演化（加约束、增跳数、转具体场景）与广度演化（跨类比生成新题） | 可控地把简单题推向高复杂度区间 | 连续演化超过 3–4 轮易产生自相矛盾的“伪难题”；每轮须经可解性校验 |
| **反演激活（Magpie）** | 仅向强对齐模型输入用户角色前缀（如 `<\|user\|>`），直接自回归采样出模型内部隐含的真实指令分布 | 零种子依赖、极低成本快速覆盖常见用户意图 | 天然偏向高频大众问题，长尾硬核领域稀缺；须叠加 Taxonomy 限流 |
| **角色驱动（Persona-driven）** | 构建 $10^5\text{–}10^6$ 级差异化人物画像（职业、资历、偏好、场景），让模型以该角色提出真实工作流需求 | 极大拉伸场景多样性与语言风格跨度 | 容易停留在表面角色寒暄；Prompt 中须强制输出可执行的专业任务与边界条件 |

### 能力分类树补盲的三条工程纪律

1. **按叶节点设“上限封顶 + 下限兜底”双配额**：单个二级任务桶占比严禁超过总池的 $12\%$，同时为业务高价值但自然分布极稀疏的长尾桶（如复杂表格核对、多轮条件变更纠错）锁定至少 $1\%\text{–}2\%$ 的保底配额。
2. **用覆盖熵追踪合成边际收益**：每补一批合成数据，实时重算标签分布香农熵 $H_{\text{tag}} = -\sum_k p_k \log p_k$ 与空桶率；若新增 1 万条合成指令后 $H_{\text{tag}}$ 不再抬升，说明合成模板已经陷入模式坍缩，必须立刻切换种子源或 Persona 分布。
3. **强制混入真实业务“脏输入”分布**：合成指令往往语法过于工整、标点一丝不苟，而线上真实用户充满错别字、口语省略与上下文跳跃；需在各叶节点按 $15\%\text{–}20\%$ 比例混入脱敏真实用户提问或其噪声增广变体。

## 8.3 复杂度 × 质量二维筛选（DEITA / InsTag）与语义去重

拿到候选池之后，决定 SFT 上限的核心步骤是**把“指令有多难”和“回答有多好”彻底解耦打分**。单维质量打分器有个致命盲区：一道“把下面三句话翻译成法语”的完美回答也能拿 $5.5/6.0$ 分，而一道多步边界分析题的优质回答同样是 $5.5$ 分；如果只按质量分排序，简单题会把难题彻底挤出训练配额。

DEITA 范式给出了简洁而高效的二维筛选口径：分别用微调的小型打分器（或校准后的裁判模型）输出每条样本的指令复杂度 $C_i \in [1, 6]$ 与回复质量 $Q_i \in [1, 6]$，构造联合演化价值分 $S_i = C_i \cdot Q_i$。在每个 Taxonomy 桶内按 $S_i$ 从高到低贪心入池——每考察一条候选样本 $(x_i, y_i)$，先计算其指令嵌入 $\mathbf{e}_i$ 与已入选同类样本最近邻的余弦相似度：

$$
\text{accept}(i) \;=\; \mathbb{I}\!\left[C_i \ge C_{\min} \;\land\; Q_i \ge Q_{\min} \;\land\; \max_{j \in \mathcal{S}_{\text{kept}}} \cos(\mathbf{e}_i, \mathbf{e}_j) < \tau_{\text{cos}}\right]
$$

**数值对比直觉**：假设两条候选样本竞争同一编程子桶配额——样本 A 为“用 Python 写冒泡排序”（$C_A = 1.6,\; Q_A = 5.6 \Rightarrow S_A = 8.96$），样本 B 为“给定并发连接池偶发死锁的日志栈，定位锁顺序反转并给出带超时回退的异步重构补丁”（$C_B = 5.4,\; Q_B = 5.2 \Rightarrow S_B = 28.08$），而样本 C 同样提出高难分布式共识问题却在回复中编造了不存在的 Raft 选举定理（$C_C = 5.6,\; Q_C = 2.1 \Rightarrow S_C = 11.76$ 且触发 $Q_C < Q_{\min} = 4.5$ 硬熔断）。二维网格精准选中 B、限流抽样 A、彻底斩杀毒化样本 C。

## 8.4 Long-CoT 冷启动：强模型蒸馏、拒绝采样与防过度思考清洗

面向推理模型（如 o1 / DeepSeek-R1 / Qwen3-Thinking 范式），SFT 阶段新增了一项极其关键的任务——**Long-CoT 冷启动数据构造**。核心方法是以强推理模型为教师执行<strong><a class="term-ref" href="/books/llm-data/glossary#rejection_sampling" title="对每道题采样多条候选推理路径，经确定性验证器或高置信裁判过滤错误与低质轨迹后保留通过样本的微调范式">拒绝采样（Rejection Sampling / RFT）</a></strong>：对每道带确定性答案的难题独立采样 $K = 8\text{–}16$ 条包含完整 `<think>...</think>` 思考块的轨迹，再用验证器与结构体检筛出最优路径。

然而，“答案做对了”远不等于“思维链适合拿来训 SFT”。未经体检的原生 Long-CoT 蒸馏数据通常潜藏四类顽疾，必须通过自动化体检闸门逐项拦截：

| 思维链顽疾类型 | 典型症状与危害 | 自动化检测指标与入库红线 |
| --- | --- | --- |
| **复读与局部死循环** | 反复输出 “Wait, let me double check...” 数十次，把卡顿口癖固化进权重 | 滑动窗口 8-gram 重复率 $< 0.15$，连续相同语义段 $\le 2$ 次 |
| **语种漂移与格式污染** | 中文提问中途无故切英文、缺少 `</think>` 闭合或答案漏在思考块内 | 主语种一致率 $> 95\%$，严格正则校验单对 `<think>...</think>` 闭合 |
| **过度思考（Overthinking）** | 简单基础题反复验算 4,000+ tokens，推高延迟并诱发短任务<a class="term-ref" href="/books/llm-data/glossary#negative_transfer" title="后训练中上调某类数据后导致另一类基础能力回退的多任务干扰现象">负迁移</a> | 剔除超过同题正确轨迹中位长度 $3\times$ 的异常长尾；优先选最短清晰有效解 |
| **巧合蒙对（Coincidental Match）** | 中间推导存在明显算术或逻辑错误，尾部负负得正凑巧命中标准答案 | 对高难核心题引入轻量步骤校验裁判（Process Audit）或人类抽审拦截 |

**完整算例：1 万道难题的 Long-CoT 冷启动成本与留存账本**。按全书统一基准口径（[核心公式与数据账本速查卡](/books/llm-data/toolkit/formulas-and-ledgers)），选定 $10{,}000$ 道去污后的数学/代码/逻辑难题，每题并行采样 $K=8$ 条轨迹（共 $80{,}000$ 条，平均输入 $400$ tokens、输出 $4{,}500$ tokens）。以离线批推理单价 $c_{\text{in}} = \$0.20/\text{1M}$、$c_{\text{out}} = \$0.60/\text{1M}$ 计：
- 单条轨迹生成费 $C_{\text{gen}} = (400 \times 0.20 + 4{,}500 \times 0.60) / 10^6 = \$0.00278$，全量 $80{,}000$ 条总推理费仅 **$222.4**。
- 经符号/单测硬验证通过率 $45\%$（剩余 $36{,}000$ 条）；再经上述四项思维链体检闸门留存 $65\%$，得到 $23{,}400$ 条干净轨迹（端到端 $\eta_{\text{pass}} = 29.25\%$）。
- 覆盖 $7{,}800$ 道唯一难题；对每题按“在保证有完整验算步骤前提下优先取较短且结构清晰路径”（Shortest-Valid Anti-Overthinking）选出 1 条主路径入库，单位有效冷启动难题成本仅 **$0.029 / 题**！

## 8.5 SFT 序列打包、多轮 Loss Mask 与 Epoch 预算控制

最后一道常被轻视的工程细节发生在“数据送入训练器之前”的序列化打包环节。三条实操纪律直接决定 SFT 能否干净收敛：

1. **多轮对话严格 Assistant-only 掩码**：在多轮指令中，只有模型扮演的 Assistant 回复（含 `<think>` 思考块与最终答复以及对应的结束符 `<|im_end|>`）参与交叉熵计算（$m_t = 1$）；System 提示与全部 User 轮次严格置 $0$。千万不要误把结束符 `<|im_end|>` 一并掩码掉，否则模型上线后会彻底丧失停止生成的能力而无限复读。
2. **思考与非思考模式显式路由协议**：如果目标模型同时服务深度推理与日常低延迟对话，切忌把 Long-CoT 与普通短回复在完全相同的系统模板下裸混。应在 SFT 阶段显式建立控制开关（如特定控制 Token 区分 Thinking / Non-Thinking），并在 Thinking 模式下也为简单常识题提供 50–120 tokens 即果断收口的精简思考范例，从源头根治“问 1+1 思考三分钟”。
3. **严控重复轮数 $E$ 防过拟合**：高信噪比 50K 指令包配合余弦退火，通常在 $E = 2\text{–}3$ 个 Epoch 达到泛化最优；超过 5 个 Epoch 后，训练 Loss 继续下降而验证集上的指令泛化与回复多样性反而明显倒退。

### 算力与信噪比对比账：50K 精选 vs 2M 原始混拼

以 32B 密集模型在 8×H100 节点上执行全参 SFT（平均样本长度 2,048 tokens，有效吞吐 ~32K tokens/s）计：
- **2M 原始噪声池（$E = 2$）**：总消耗 $D_{\text{tok}} = 8.19\text{B}$ tokens，耗时 **71.1 小时**（约 $\$2{,}275$ 算力费），但其中超过 85% 的梯度消耗在同质模板与低质回复上，下游复杂指令与数学推理反而出现回退。
- **50K 高信噪比金标（$E = 3$）**：总消耗 $D_{\text{tok}} = 307\text{M}$ tokens，仅耗时 **2.7 小时**（约 $\$86$ 算力费），在大幅节省 96% 训练算力的同时，将迭代消融周期从三天压到一顿午饭时间。

::: tip 工程最佳实践：用“模板渲染回放测试”守住 SFT 入库最后一公里
每次打包 SFT 训练集前，务必随机抽取 100 条覆盖单轮、多轮、代码块、Long-CoT 与工具调用的样本，执行 `tokenizer.decode` 可视化回放：绿色高亮 $m_t=1$ 区域、灰色显示 $m_t=0$ 区域，逐字核验空格拼接、换行符、结束符与特殊控制 Token 是否精准切分为单 ID。历史上大量“调了两周超参怎么都训不动”的离奇故障，根因都藏在一个被误切或漏掩码的换行符里。
:::

::: warning 红线警示：严禁跨版本无校验复用旧 SFT 包
每次更换基座模型、升级分词器或扩充评测基准后，必须重新核验两件事：一是特殊控制 Token 是否与新分词器词表一一对齐；二是在最新评测集全集上重跑 N-gram 与语义去污，防止历史沉淀下来的 SFT 包悄悄引入基准泄漏。
:::

高质量的 SFT 与 Long-CoT 冷启动已经把基座打磨成一名“懂规矩、会思考”的合格选手；但面对没有唯一标准答案的开放写作、复杂方案设计、语气边界与细腻偏好，仅靠单一标准回复的交叉熵拟合远远不够。下一章我们将进入偏好数据、原子化评分细则（Rubric）与人类专家标注工厂的精密工程世界。
