## 21.1 离线批合成的算力账本：从满载调度到双级缓存复用

离线批合成（Offline Batch Synthesis）与线上实时对话服务有着截然不同的物理约束。线上推理被首字延迟（TTFT）与单用户解码吞吐（TPOT）死死卡住，往往只能跑在低并发的访存受限（Memory-bound）区；而数据合成任务没有人类盯着屏幕等待，其唯一优化目标是在显存容量内**把 GPU 算力利用率推到计算受限（Compute-bound）满载区，压低每百万有效 Token 的电费与折旧成本**。正如 [《LLM 推理工程》](/books/llm-inference/) 系统拆解的底层优化栈，工业级批合成引擎（vLLM / SGLang）主要靠四根杠杆榨出 5–15 倍吞吐红利：

| 优化杠杆 | 核心机理与配置要点 | 典型收益 | 适用数据合成场景 |
| --- | --- | --- | --- |
| **高并发连续批处理与 FP8** | 调大 `max_num_seqs` 与 Chunked Prefill，关闭单请求延迟保护；在 Hopper/Blackwell 上启用 FP8 权重与 KV Cache | 单位 GPU 吞吐提升 **3–5×** | 预训练网页改写、密集重打标、海量 QA 初筛 |
| **RadixAttention / Prefix Caching** | 将共享系统提示、工具 Schema、长背景文档与多轮前序历史以基数树复用 KV 块，只对增量后缀做 Prefill | 输入 Prefill 算力直降 **60%–85%** | 多轮 Agent 轨迹展开、单文档多题派生、Pass@k 组采样 |
| **多模态视觉编码缓存（ViT Cache）** | 对同一张高分辨率截图或视频帧，ViT 视觉编码与投影只跑一次并缓存视觉 Token 嵌入，供 $N$ 路并行采样复用 | 视觉编码耗时压降 **$N\times$**（常达 **4–16×**） | GUI 定位多采样、图表密集重打标、Visual CoT 拒绝采样 |
| **按长度分桶与树形拓扑调度** | 请求按预估上下文长度分组并优先把同前缀请求路由至同一推理副本（Prefix-aware Routing），避免缓存抖动 | 缓存命中率从 ~20% 拉升至 **>75%** | 多节点大集群离线批合成作业 |

### 离线吞吐与自托管单价直觉核算

以一台自托管 **8×H100 节点**（市场折旧与电费口径约 **\$24 / 小时**）部署 FP8 量化 32B 开源教师模型为例：
- **严苛线上 SLA 模式**：为保住单用户解码速度 $> 60\text{ tok/s}$，并发批大小受限，整机有效输出吞吐常停留在约 **$3{,}500\text{ tok/s}$**（每小时 $12.6\text{M}$ tokens），对应纯输出算力成本约 **\$1.90 / 1M tokens**。
- **离线满载批合成模式**：放开批大小至 256+、启用 Chunked Prefill 与 RadixAttention 共享长上下文后，整机有效输出吞吐跃升至 **$18{,}000\text{–}24{,}000\text{ tok/s}$**（每小时 $64.8\text{M}\text{–}86.4\text{M}$ tokens），折算输出单价直降至 **\$0.28–\$0.37 / 1M tokens**（算上调度冗余与存储约 **\$0.45 / 1M tokens**），与商用 API 相比瞬间拉开一个数量级的成本代差。

> **多轮轨迹里的二次方重算陷阱**：一条 10 轮的 Agent 交互若每轮增长 800 tokens，无前缀缓存时累计 Prefill Token 数为 $800 \times (1 + 2 + \dots + 10) = 44{,}000$ tokens（其中超过 80% 都是重复计算的旧历史）。开启 Prefix-aware 路由 + RadixAttention 后，前序历史零重算，仅需计算增量观测与动作，批合成引擎瞬间释放出数倍真实有效算力。

## 21.2 强弱模型级联与单位有效样本成本公式

单纯压低单次推理价格还远远不够——合成数据工程最容易掉进的财务误区，是**只看每百万 Token 报价，却忽略失败废弃率、沙箱消耗与人工抽检税**。对照 [核心公式、数据账本与成本速查卡](/books/llm-data/toolkit/formulas-and-ledgers)，全书统一的**单位有效样本成本公式**为：

$$
C_{\text{eff}} \;=\; \frac{C_{\text{gen}} + C_{\text{env}} + C_{\text{verify}}}{\eta_{\text{pass}}} \;+\; \gamma_{\text{audit}} \cdot C_{\text{human}}, \qquad
C_{\text{gen}} = \frac{L_{\text{in}} c_{\text{in}} + L_{\text{out}} c_{\text{out}}}{10^6}
$$

其中 $\eta_{\text{pass}} \in (0, 1]$ 是经格式解析、去伪过滤与确定性验证后的端到端通过率，$C_{\text{env}}$ 为容器/检索/API 环境开销，$C_{\text{verify}}$ 为验证器或裁判开销，$\gamma_{\text{audit}}$ 为入库前人工质检抽样比。公式一眼暴露了降本增效的三个主战场：
1. **压分子 $C_{\text{gen}}$（强弱级联路由）**：先用自托管 8B–32B 开源批引擎低价扫 100% 样本并经廉价校验器过滤，仅将触发三类升级条件的 15%–25% 难题交给旗舰模型接管——① 格式/Schema 连续解析失败；② 确定性单元测试或环境断言未过；③ 多采样自洽度低或裁判打分处于灰区。对多轮 Agent 失败轨迹，更可结合第 19 章<a class="term-ref" href="/books/llm-data/glossary#counterfactual_repair" title="精准定位失败轨迹首个关键偏航步，回滚沙箱后由强模型修正动作">反事实修复</a>只让旗舰模型重做单个关键分叉步。
2. **抬分母 $\eta_{\text{pass}}$（前置筛选）**：前置题目难度分桶与沙箱预热，提前剔除无解死题与环境依赖缺失题；把 $\eta_{\text{pass}}$ 从 15% 提到 30%，等价于凭空砍掉一半全链路算力账单。
3. **控尾项 $\gamma_{\text{audit}} \cdot C_{\text{human}}$（强验证器替代人海抽检）**：确定性验证器能把人工质检比压至 0.5%–1%；若缺少可靠自动验证器而依赖 10% 人工复核，即便 GPU 免费，审计税也会反超全链路总成本。

### 完整数值算例：生产 10,000 条有效多轮 Agent 轨迹的三套账本

沿用全书 2026 基准口径：单条 10 轮轨迹累计输入 $L_{\text{in}} = 40{,}000$ tokens、输出 $L_{\text{out}} = 4{,}000$ tokens，领域专家人工精标单价 $C_{\text{human}} = \$35.00$。对比三条工业路线：

| 生产方案 | 单次生成 $C_{\text{gen}}$ | 环境与验证 $C_{\text{env}}+C_{\text{verify}}$ | 通过率 $\eta_{\text{pass}}$ | 人工抽检税 $\gamma_{\text{audit}} C_{\text{human}}$ | 单位有效成本 $C_{\text{eff}}$ | 10,000 条总预算 |
| --- | --- | --- | --- | --- | --- | --- |
| **方案 A：纯人工专家录屏精标** | — | — | 85%（已摊入） | 全额人工 | **\$35.00 / 条** | **\$350,000**（耗时数月） |
| **方案 B：朴素旗舰 API 直出（无缓存）** | \$0.180（\$3 / \$15 每百万） | \$0.025 + \$0.005 | 15% | 2.0% × \$35 = \$0.700 | **\$2.10 / 条** | **\$21,000** |
| **方案 C：32B 缓存批推理 + 20% 旗舰级联 + 强验证** | **\$0.025**（75% 前缀缓存命中） | \$0.015 + \$0.002 | **28%** | 0.5% × \$35 = \$0.175 | **\$0.325 / 条** | **\$3,250**（天级产出） |

逐项核对方案 C 的精确算术，看清每一分钱到底省在了哪里：

- **常规 80% 路径（自托管 FP8 32B 批引擎）**：基础单价 \$0.15 / \$0.45，75% 缓存命中部分按 20% 计费后有效输入单价降至 $\$0.15 \times (0.25 + 0.75 \times 0.2) = \$0.06/\text{1M}$，单次生成仅 $C_{\text{gen}}^{\text{weak}} = (40{,}000\times 0.06 + 4{,}000\times 0.45)/10^6 = \$0.0042$；
- **升级 20% 路径（开启前缀缓存的旗舰模型）**：有效输入单价 $\$3.00 \times 0.40 = \$1.20/\text{1M}$、输出 $\$15.00/\text{1M}$，单次生成 $C_{\text{gen}}^{\text{strong}} = (40{,}000\times 1.20 + 4{,}000\times 15.00)/10^6 = \$0.1080$；
- **加权汇总与通过率折算**：混合平均生成费 $\bar C_{\text{gen}} = 0.8\times 0.0042 + 0.2\times 0.1080 = \$0.025$，叠加容器池复用后的 $C_{\text{env}}+C_{\text{verify}} = \$0.017$，单次尝试合计 \$0.042；除以 $\eta_{\text{pass}} = 0.28$ 得算力与沙箱净成本 **\$0.150**；
- **人工抽检尾项的反直觉结论**：加上 0.5% 人工抽检费 **\$0.175**，最终 $C_{\text{eff}} = \$0.325$——**较纯人工降本 108 倍，较朴素 API 直出降本 6.5 倍**。更发人深省的是：在高度优化的方案 C 里，仅 0.5% 的人工抽检费（\$0.175）就已经反超了全部 GPU 与沙箱消耗（\$0.150）！

### 多模态批合成的视觉编码缓存要点

对视觉密集重打标、GUI 定位与 Visual CoT 拒绝采样任务，单张 $1120\times 1120$ 高清图需展开约 $T_{\text{img}} = 1{,}600$ 个视觉 Token。若对同一截图做 $G = 8$ 路采样却每次重复跑 ViT 编码器，不仅浪费近 8 倍视觉前端算力，更会挤爆跨节点图片传输带宽。工业批引擎应以 `image_sha256 + resolution_tile_cfg` 为键将 ViT 投影后的 KV/视觉特征常驻缓存，并将同图多采样请求打包进同一调度批次执行。

## 21.3 模型坍缩机理：尾部蒸发与方差发散

当合成成本被压低两个数量级后，团队往往按捺不住冲动：用第 $k$ 代模型生成语料直接替代稀缺的真实数据，滚动训练第 $k+1$ 代模型。如果缺乏外部真值锚定，这条“左脚踩右脚”的捷径很快就会触发<a class="term-ref" href="/books/llm-data/glossary#model_collapse" title="模型反复在自身或同族模型生成的合成数据上递归训练且缺乏真实世界锚定时的分布退化现象">模型坍缩（Model Collapse）</a>，直接侵蚀全书核心账本中的<a class="term-ref" href="/books/llm-data/glossary#effective_tokens" title="扣除重复衰减、噪声清洗损益、污染与自噬折损后的真实折算有效数据量">有效数据量</a> $D_{\text{eff}}$。

模型坍缩并非一夜崩溃，而是分两阶段悄然发作：
- **早期坍缩（尾部蒸发，Tail Evaporation）**：解码阶段为了保证流畅度通常使用低温采样或 Top-p 截断，低概率长尾知识、罕见边界语法、少数领域案例最先落入采样截断区而从下一代训练集中永远消失。例如，一个初始出现概率 $p_0 = 5\times 10^{-4}$ 的长尾专有概念，在有限采样量 $n = 2{,}000$ 下单代零命中的概率高达 $(1 - 5\times 10^{-4})^{2000} \approx 36.8\%$，叠加 Top-p 截断后往往在 2–3 代内彻底归零；而此时常规主流榜单分数甚至可能短期微涨，掩盖了泛化分布悄然收窄的暗伤。
- **晚期坍缩（模式塌陷与分布漂移，Mode Collapse）**：每代有限样本的重采样误差与模型架构近似误差逐代累积放大，最终导致输出高度模板化、句式僵化、幻觉互相强化，直到分布坍缩为若干高频空话。

在每代仅用上一代生成样本**完全替换（Replace）**真实数据的简化高斯模型下，第 $k$ 代估计均值 $\hat\mu_k$ 的方差随代数单调线性发散，协方差矩阵行列式指数级趋零（完整推导与累加混合定理见 [专题 B：合成数据与模型坍缩的理论边界](/books/llm-data/topics/model-collapse-theory)）：

$$
\mathrm{Var}(\hat\mu_k) \;=\; \sigma_0^2 \cdot \left(\frac{1}{n_0} + \sum_{j=1}^{k}\frac{1}{n_j}\right) \xrightarrow{k\to\infty} \infty
$$

从信息论视角看，无外部校验的闭环自生成严格受限于**数据处理不等式（Data Processing Inequality）**：在封闭马尔可夫链 $X_{\text{real}} \to \hat\theta_1 \to \tilde X_1 \to \hat\theta_2$ 中，关于真实世界的互信息 $I(X_{\text{real}}; \hat\theta_k)$ 只能单调递减，模型绝不可能靠封闭自言自语凭空生出世界新知识。

## 21.4 工业级四重抗坍缩防线与在线多样性监控

既然模型坍缩的根源在于“替换丢弃真源”与“零外部新信息闭环”，工业界大规模使用合成数据（如 Phi、Nemotron-CC、DeepSeek-R1 路线）之所以越训越强而非越训越傻，靠的是严密落地的**四重抗坍缩护栏**：

1. **累加混合与真实种子锚定（Accumulating with Real Grounding）**：严禁用合成数据替换历史真实语料库，必须在混合配方中为真实世界高质数据保留硬性底线比例（预训练与长程迭代通常锁定真数不低于 30%–50%），并让每条合成指令都从真实网页、代码仓、论文或业务工单种子出发改写，将估计方差上界牢牢钉死在真实样本锚点上。
2. **外部真值环境校验（External Grounding）**：接入编译器、单元测试套件、形式化证明器、搜索引擎或真实沙箱终态断言。外部验证器通过淘汰错误轨迹、留下可验证成功路径，实质上是向闭环里**注入了来自物理/逻辑世界的真实信息位**，打破自噬退化（同时需用第 19 章机制剔除<a class="term-ref" href="/books/llm-data/glossary#lucky_hack" title="虽侥幸触发终态通过判定但中间逻辑存在严重缺陷的毒化轨迹">假成功轨迹</a>）。
3. **跨家族异构模型混血（Cross-family Mixing）**：不要只用单一模型家族既当出题者、又当答题者、还当裁判员。在生成池与裁判池中混合 2–3 个不同预训练底座与架构家族，打断单一模型的“高频口头禅”（如过度使用破折号、固定分点套话）与同源盲区共振。
4. **在线多样性与尾部熵监控（Live Diversity & Entropy Telemetry）**：将以下四项指标写入批合成管线的自动化阻断门槛，任何一项跌破基线即自动熔断并排查采样温度、提示模板或过滤阈值：
   - **词汇与结构熵**：Distinct-3 / Distinct-4 n-gram 占比、句式开头分布熵与回复长度方差；
   - **语义覆盖密度**：将批产出向量化投影至能力分类树，监控长尾叶节点占比与簇内平均余弦相似度（防语义趋同）；
   - **压缩率与重复警报**：批文本 gzip 压缩比突降往往是模型掉进模板复读机的最快早期信号；
   - **尾部知识金丝雀评测**：保留一组低频长尾知识与边缘代码语法探针题，在每次新合成批次并入前检查是否出现“主流分微涨、长尾分暗跌”的早期坍缩征兆。

::: tip 工程黄金法则：先算验证器信息增益，再放大合成倍率
并非所有任务都适合无上限合成。对**可验证非对称任务**（代码、数学、SQL、沙箱 Agent，验证远比生成便宜且零幻觉），外部真值源源不断注入信息，合成占比可安全推高至 60%–80%；对**开放式主观创作与事实百科**，缺乏硬验证器，合成数据必须严格限制为真实种子的结构化改写或高质量 Rubric 引导，并始终以高比例真实人工样本压舱。
:::

::: warning 警惕“互联网二次污染”引发的隐性坍缩
