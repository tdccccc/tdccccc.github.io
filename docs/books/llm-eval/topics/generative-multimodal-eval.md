# 专题 D：多模态生成（图 / 视频 / 端到端语音）评测速览

<p class="chapter-summary">跳出纯文本与视觉理解边界，高密度速览文生图、视频生成与端到端实时语音 Agent 三大生成模态的评测演进：从饱和的 FID / WER 走向组合构图校验、物理时序一致性与全双工口语工具调用评测。</p>

本书 [第 6 章](/books/llm-eval/chapters/chapter-06) 聚焦“看图答题”的视觉理解底座（VLM），但企业多模态应用正迅速延伸至营销设计文生图、广告与仿真视频生成，以及电话客服/车载端到端语音交互 Agent。尽管像素、视频帧与声波形态迥异，三大生成模态的评测演进却惊人地遵循着同一条三段式规律：**早期分布/信号距离指标饱和失真 → 细粒度结构化约束与多模态评委兴起 → 控制协变量的人类盲测 Arena 与业务终态验证闭环**。

---

## D.1 文生图（Text-to-Image）：从 FID / CLIPScore 饱和到组合构图校验

在早期扩散模型时代，<strong>FID（Fréchet Inception Distance）</strong>与 **CLIPScore** 是标配指标；但进入 FLUX、SD3.5、Midjourney 与原生多模态生图时代后，这两项老指标几乎彻底丧失了选型区分度：
- **FID 与审美背离**：FID 衡量生成图与 COCO 等老旧参考集的特征分布距离，高审美现代模型常因为构图和光影“比 COCO 照片更好看”反而拿到更差的 FID。
- **CLIPScore 的“词袋盲区”**：CLIP 编码器对空间方位、数量和属性绑定极度迟钝——提示词写“红色立方体在蓝色球体左侧”，模型画成“蓝色立方体在红色球体右侧”，CLIPScore 照样打高分。

现代文生图工程评测已收敛为三层标尺：
1. **程序化目标检测与组合遵循（GenEval 与 DPG-Bench）**：
   - **GenEval**（Ghosh 等，2023）借助目标检测与颜色分类器，硬核核验六大原子构图维度：单物体存在、双物体共存、精确数量计数、颜色绑定、相对空间位置（上下左右）以及属性交叉绑定；
   - **DPG-Bench**（Hu 等，2024）面向百词级稠密长提示，将复杂描述拆解为多组实体—属性原子 VQA 题目逐项核查，专门弥补 GenEval 提示词过短、难以测出长段细节遗漏的盲区。
2. **VLM-as-a-Judge 细则裁判（VQAScore / DSG / 文字渲染）**：相比容易饱和的全局相似度，VQAScore 直接计算 VLM 对 `Does this figure show "{prompt}"?` 回答 `Yes` 的条件概率，对否定词、复杂关系与多实体组合灵敏度远高于 CLIPScore；面向海报与电商图还需叠加 **OCR 编辑距离 / 零错字率** 与人物手部解剖畸变 Rubric（同样须复用 [第 3 章](/books/llm-eval/chapters/chapter-03) 的评委偏差校准）。
3. **盲测偏好排名（Image Arena）**：沿用 [第 2 章](/books/llm-eval/chapters/chapter-02) 的<a class="term-ref" href="/books/llm-eval/glossary#bradley_terry_elo" title="拟合人类成对盲测胜率并换算为 Elo 评分的统计排名方法">Bradley-Terry 模型与 Arena Elo</a> 收集大规模人类双盲对比；工程审计时需像<a class="term-ref" href="/books/llm-eval/glossary#style_control" title="在盲测回归中剥离纯表面风格协变量，测出真实内容实力">风格控制</a>一样拆离“高饱和度高对比度滤镜偏见”与“严格遵循提示词”的差异。

## D.2 视频生成（Text / Image-to-Video）：视觉美感 vs 时序一致与物理常识

视频生成最容易出现<strong>「每一帧截出来都是壁纸，连起来看却违背物理常识」</strong>的割裂现象（如人物转身换脸、液体倒流、穿透刚体或手指随帧增减）。因此单纯沿用单帧图像美学分或早期 FVD（Fréchet Video Distance）极易误判。

- **VBench / VBench++（Huang 等，2024）**：当前视频生成最主流的解耦基准，将评测系统拆解为 **16+ 项细粒度维度**：
  - **视频质量轴（Video Quality）**：拆解主体一致性（DINO 特征跨帧稳定）、背景一致性、时间闪烁度（Temporal Flickering）、运动平滑度、画质与审美质量，并强制捆绑<strong>动态幅度（Dynamic Degree）</strong>作为反作弊阀——否则模型只要把视频画成“几乎静止的幻灯片”，就能在主体一致性和平滑度上轻松刷出满分；
  - **条件对齐轴（Condition Alignment）**：逐项检验物体类别、多物体共存、人类动作语义、空间关系、色泽风格与镜头运镜控制（推拉摇移）。
- **物理合理性与分层盲测协议（VideoPhy / PhyGenBench）**：
  - **刚体与流体因果检验**：测试自由落体加速度、碰撞反弹、水杯倾倒与物体遮挡重现（Object Permanence），揪出“画面精良但物理崩坏”的典型生成瑕疵；
  - **按运动幅度分层的人类盲测**：开展成对双盲对比时，将测试集按**静态空镜、中速镜头推进、多主体大动作交互**三档分层汇报胜率与 Bradley-Terry Elo，彻底封堵“以静换稳”的作弊捷径；
  - **长时身份与口型一致性**：面向营销短视频与数字人业务，补充跨 5–10 秒镜头切换后的人脸余弦相似度与音画唇形同步偏移（AV Sync Offset）指标。

## D.3 端到端语音与实时对话 Agent（Speech / Voice Agents）

传统“ASR 转文字 → LLM 生成 → TTS 合成”级联链路习惯用 **WER / CER（词/字错率）** 测听写、用 **MOS / UTMOS** 测音质自然度。但在原生端到端语音模型（Speech-to-Speech，如 GPT-4o Realtime、Gemini Live、Moshi、Qwen-Omni）走向客服热线与智能座舱后，上述静态指标完全抓不住决定用户体验生死的四大核心维度：

1. **全双工打断与轮次响应延迟（Full-Duplex & Turn-Taking）**：真实人类通话随时会插话、犹豫与附和，模型既不能迟钝半拍，也不能一有环境杂音就乱停或频繁抢话。
2. **副语言韵律与情绪保留（Prosody & Emotion Preservation）**：级联 ASR 最大的信息损耗是把语气、讽刺、焦急、口音与重音全部抹平为干巴巴的文字。端到端评测（如 **VoiceBench / AudioBench / AIR-Bench** 及双盲人类打分）需专门构造“字面相同、语气截然相反”的样本，验证模型能否直接从声学特征听出情绪并输出匹配的安抚语调与语速。
3. **嘈杂口语到工具调用准确率（Spoken-to-Tool-Call）**：对企业语音 Agent 而言，最致命的失败发生在**直接从带地方口音、口吃、中英混说、自我更正（“不对，尾号是 87 改成 78”）与 8kHz 电话底噪的音频流中提取结构化槽位并调用外部工具**。评测必须以 [第 9 章](/books/llm-eval/chapters/chapter-09) 与 [第 18 章](/books/llm-eval/chapters/chapter-18) 的**终态断言**为准绳，直接核验音频输入端到端触发的 API 参数精确度。
4. **声学安全与语音注入边界**：除常规文本红线外，还需防备音频层面的越狱诱导、人声情绪欺骗以及背景音频中混入的间接指令干扰。

### 语音 Agent 核心压测指标与真实音频集构造

构建企业级语音黄金评测集时，严禁只拿干净的 TTS 合成音频跑通就放行——必须覆盖四类真实声学扰动：
- **窄带电话信道与环境噪声**：8kHz / G.711 编解码降质叠加商场、地铁、车载风噪；
- **非流利口语与中途改口**：停顿、重复、口头禅以及话中推翻前序数字或日期；
- **中英混说与专有名词**：英文 SKU、品牌缩写与地方口音交织；
- **主动叠音插话脚本**：在 Agent 播报至第 1–2 秒时精准注入用户打断音频流。

对照下表完成上线准入验收：

| 语音 Agent 核心指标 | 测量口径 | 典型生产参考门槛 | 常见线上失效现象 |
| --- | --- | --- | --- |
| **首音节响应延迟（TTFA）** | 用户话尾静音判定至首帧合成音频吐出 P95 | $< 500\text{ ms}$（越近人类对话节拍越好） | 思考过长导致用户误以为掉线反复“喂？” |
| **插话打断停播延迟（Barge-in）** | 用户开口插话至 Agent 语音流彻底静音的耗时 | $< 250\text{–}300\text{ ms}$ | 双方叠音互喊，无法打断长篇播报 |
| **噪声误打断率（FIR）** | 8kHz 电话底噪、咳嗽、键盘声误触发停播占比 | $< 3\%$ | 车载/户外场景下 Agent 说话断断续续 |
| **口语→工具参数终态率** | 含口音/自我更正/数字串音频直出的 API 终态准确率 | 核心业务槽位 $\ge 98\%$ + 高危动作语音二次确认 | 把“改签 18 号”听成“8 号”且未经确认直接下单 |

## D.4 三大生成模态评测选型速查矩阵

| 生成模态 | 已饱和/失真老指标 | 当前主流工程基准 | 最常见“刷分漏洞” | 企业落地必测私有项 |
| --- | --- | --- | --- | --- |
| **文生图** | COCO-FID · CLIPScore | GenEval · DPG-Bench · VQAScore · Image Arena | 靠高对比滤镜赢审美票，却漏画物体数量与方位 | 品牌 Logo/包装文字 OCR 零错字率、商品一致性与合规版权审查 |
| **视频生成** | FVD · 单帧美学均分 | VBench / VBench++ · VideoPhy · 运动分层盲测 | **“静态图片作弊”**：画面几乎不动换取高一致性分 | 固定运动幅度分桶下的主体保真度、物理常识失误率与口型同步 |
| **端到端语音 Agent** | 单句 WER · 离线 MOS | VoiceBench · AudioBench · 全双工压测套件 | 安静棚录高分，真实电话 8kHz 噪声+插话立刻崩溃 | TTFA / 打断延迟 P95、带口音自我更正后的**口语→工具参数终态准确率** |

::: tip 跨模态统一工程铁律
无论评测图像、视频还是端到端音频，只要引入了 VLM / ALM 充当自动化评委，都必须复用本书 [第 3 章](/books/llm-eval/chapters/chapter-03) 的 **人类小样本金标标定 $(q_1, q_0)$ + Rogan-Gladen 矫正** 流程，并警惕多模态评委自身的“偏爱高饱和画面 / 偏爱甜美慢速音色”表面风格偏见。
:::
