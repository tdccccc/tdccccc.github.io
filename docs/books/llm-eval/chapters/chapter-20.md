# 第 20 章 从评测到演进：脚手架重构、SFT 与 RLVR 后训练闭环

<p class="chapter-summary">三部曲总收官：建立“改脚手架（Harness Engineering）vs 改模型（SFT / DPO / RLVR）”归因决策矩阵，确立失败轨迹安全转化为后训练数据的物理隔离防污染红线，并展望可扩展监督、防隐藏能力（Sandbagging）与自适应考试前沿。</p>

评测从来不是终点，而是驱动系统演进的罗盘。经过前十九章的武装，团队手里已经握有高信噪比的黄金集、校准过的判分器、全链路 Tracing 以及由 Open Coding 提炼出的精准失败谱系。接下来摆在技术负责人面前最昂贵、也最容易做错的决策只有一个：<strong>面对评测暴露出的短板，究竟该改外围脚手架，还是该启动模型后训练？</strong>

本章作为《LLM 与 Agent 评测》乃至整个<strong>「推理 × 强化学习 × 评测」</strong>三部曲的总收官，彻底打通评测与系统演进的最后一公里。

## 20.1 改脚手架（Harness Engineering）vs 改模型：归因决策矩阵

大模型工程界最昂贵的常见弯路，是把本该用三行脚手架代码解决的问题，拿去烧几万卡时跑微调与强化学习。一条贯穿生产实践的第一原则是：<strong>永远先榨干<a class="term-ref" href="/books/llm-eval/glossary#scaffold" title="脚手架：包裹在底层 LLM 之外的提示词、工具封装、编排与校验循环总称">脚手架</a>与上下文工程的红利，再动用后训练重武器</strong>。脚手架改动以小时或天计、零算力训卡成本、可瞬时灰度回滚；而 SFT / RLVR 不仅耗时数周，还会立刻背上“灾难性遗忘评估、私有权重托管、每次底座升级被迫重训”的长期运维税。

但脚手架也有清晰的物理天花板。我们可以用两个可测的诊断维度——**问题根因所在层级**与**多采样覆盖率** $\widehat{\mathrm{pass@}k}$——构成一张精确的四象限归因决策矩阵：

| 评测暴露的典型症状与诊断信号 | 首选演进路径 | 底层机理与工程 ROI |
| --- | --- | --- |
| **Oracle 上下文下表现优异**，但真实链路中频繁填错工具参数、格式解析崩坏、长历史遗忘或被多余工具干扰 | <strong>重构脚手架（Harness Engineering）</strong>：精简工具数、重写 Schema 与自解释报错、拆多步子任务、外置校验器与上下文折叠 | 1–3 天上线、零训卡成本，收益常高达 +10%–25% |
| **Oracle 喂入正确文档即可答对**，核心失败是私有知识缺失、索引过时、表格切碎或业务条款高频变动 | <strong>升级检索与环境基建（RAG / 记忆 / 网关护栏）</strong>；严禁用微调硬背易变业务事实 | 知识可分钟级更新，彻底免去反复重训与过时幻觉 |
| 脚手架已极简干净，$\widehat{\mathrm{pass@}8}$ 很高（如 $>65\%$）但 $\widehat{\mathrm{pass@}1}$ 与 $\widehat{\mathrm{pass}^5}$ 偏低，或思考过长拖垮延迟 | **启动 RLVR / Agentic RL 后训练**：在可验证沙箱或细则上内化长程规划、出错自愈与思考长度压缩 | 模型已具备探索覆盖率，RL 梯度非零方差充足，能把偶发灵感拉齐为高可靠稳态 |
| Oracle 与完美脚手架下 $\widehat{\mathrm{pass@}8}$ 仍接近 $0\%$，或目标是把昂贵旗舰能力压进 7B–32B 小模型降本提速 | **SFT / DPO / 在线蒸馏（OPD）冷启动，或直接升级更强商用/开源底座** | 面对全错零方差组（见 [《LLM 强化学习》第 20 章](/books/llm-rl/chapters/chapter-20)），纯 RL 无从下嘴，需先注入新范式或蒸馏重构帕累托前沿 |

**高杠杆三步排障路由**：在拍板立项后训练前，花半天挑出 30 道代表性失败题做三步极低成本校验：
1. **Oracle 上下文消融**：手工把正确检索文档与干净工具回包塞进上下文，若通过率瞬间暴涨，立刻叫停训卡，回头修检索、切片与脚手架；
2. **剪刀差探测**：在干净脚手架下测 $\widehat{\mathrm{pass@}8} - \widehat{\mathrm{pass@}1}$；若剪刀差超过 25 个百分点，说明模型“偶尔会做但不稳”，此时投入 RLVR 或拒绝采样往往立竿见影；若 $\widehat{\mathrm{pass@}8}$ 依然极低，则必须先做 SFT / 蒸馏或换更强底座；
3. **核算帕累托与运维税**：对照第 15 章的 <a class="term-ref" href="/books/llm-eval/glossary#pareto_frontier" title="联合帕累托前沿：在质量、单任务成本与 P95 延迟三维空间中的最优折中方案集合">联合帕累托前沿</a>，仅当日调用量足够高、或私有小模型蒸馏带来的 $\$/\text{Task}$ 与 P95 延迟收益在半年内能覆盖数倍于训卡与运维的成本时，才值得维护自研权重。

> **典型归因反转案例**：某运维排障 Agent 在 300 题黄金集上初始 $\widehat{\mathrm{pass@}1}$ 仅 54%，团队原计划租用 64 卡集群做两周 SFT + RLVR。执行三步排障后发现：在 Oracle 工具回包下同一底座通过率高达 86%；Open Coding 显示 68% 的失败集中在“暴露了 42 个近似工具导致选错”与“查询接口返回原始 18 KB 日志淹没错误行”。团队暂停训卡，耗时 3 天将工具收口为 9 个按场景路由的原子接口，并在网关侧把报错回包改为带修复提示的结构化 JSON——未动一行模型权重，$\widehat{\mathrm{pass@}1}$ 直接跃升至 <strong>81%</strong>，单任务 Token 账单反降 <strong>44%</strong>。只有在此后的干净脚手架上，剩余 19% 涉及多步根因推理的短板才真正进入 RLVR 射程。

## 20.2 失败轨迹向后训练数据的安全转化与物理隔离红线

一旦确认需要启动 SFT、DPO 或 RLVR，团队立刻面临整个评测体系最危险的诱惑：<strong>“既然离线黄金集里这 120 道题模型老答错，不如直接把它们修成标准答案塞进训练集吧！”</strong>

千万按住这只手！把评测原题（哪怕是 Dev 集，更遑论 Holdout 集）直接倒进训练语料，是一条通往自我欺骗的快车道：两周后离线分数光速飙升到 98%，但一旦灰度上真流量，系统对哪怕换了两个词的新问题照错不误——你刚刚亲手制造了最经典的<strong><a class="term-ref" href="/books/llm-eval/glossary#data_contamination" title="数据污染：评测集题目、答案或其变体混入训练语料导致离线分数虚高而真实泛化不变">内部数据污染</a></strong>，彻底摧毁了全公司唯一可信的尺子。

<figure class="book-figure">
  <img src="/figures/llm-eval/eval-posttraining-loop.svg" alt="评测驱动后训练演进闭环与 Train / Dev / Holdout 物理防污染防火墙架构图" loading="lazy">
  <figcaption><span class="book-figure__label">图 20-2</span>从评测失败谱系安全驱动后训练演进的闭环架构。评测域仅向上游输出“脱题的抽象失败模式”，中央防火墙以 n-gram 与语义近邻自检严防任何原题跨界泄漏。</figcaption>
</figure>

为了既享受“评测驱动数据飞轮”的复利，又保住测量公信力，必须立下**三条不可逾越的数据防火墙铁律**：

1. **三池物理隔离**：代码仓库、对象存储与访问权限严格划分为 `Train Pool`（可自由扩增、合成与训练）、`Dev Eval Pool`（供 Open Coding 误差分析与脚手架调试，禁止进入训练管线）与 `Holdout Gate Pool`（权限锁定，对算法工程师与训练脚本均不可见，作为唯一发布准入裁判）。
2. **只传“抽象失败模式”，在同源环境程序化合成全新训练题**：
   - 从 Dev 失败轨迹中提炼脱题的抽象根因（例如“SQL 生成在多表 LEFT JOIN 时漏写软删除过滤条件”，或“遇到工具返回 HTTP 503 不懂指数退避与降级”），**彻底剥离原题实体与上下文**；
   - 基于同源程序化生成器或独立历史未入库大池，批量构造覆盖该失败模式的**全新训练题**，再按任务特性接入三路后训练：
     - **SFT / OPD 路径**：让强教师模型或当前模型多采样，经由确定性验证器或高置信度 Rubric 过滤出成功轨迹做拒绝采样微调或在线蒸馏；
     - **DPO 路径**：在同一全新训练题下配对“通过验证的正确轨迹”与“触发真实失败模式的负轨迹”做偏好对齐；
     - **RLVR / Agentic RL 路径**：把全新训练题直接挂载到与评测同构的可验证沙箱或加权 Rubrics 奖励器上跑在线强化学习——此时 [《LLM 强化学习》第 5 章](/books/llm-rl/chapters/chapter-05) 的 RLVR / RaR 评分细则奖励与 [《LLM 强化学习》第 14 章](/books/llm-rl/chapters/chapter-14) 的多轮观测损失掩码 $\mu_t$ 及 Token-in-Token-out 铁律无缝接棒，让评测基建（沙箱池、验证器、Rubric）直接复用为后训练引擎。整个转化链路可用一条统一的**防污染数据飞轮**概括：

$$
\text{Dev 失败轨迹} \xrightarrow{\text{Open Coding}} \text{抽象失败模式 } \mathcal{P} \xrightarrow{\text{同源新题合成}} \mathcal{D}_{\text{train}}^{\text{new}} \xrightarrow{\text{去污闸门}} \text{SFT / DPO / RLVR} \xrightarrow{\text{盲测裁决}} \text{Holdout Gate}
$$

三条后训练路径对评测基础设施的复用方式与验收重点各有侧重：

| 后训练路径 | 所需训练数据形态 | 复用的评测基建资产 | Holdout 盲测重点防线 |
| --- | --- | --- | --- |
| **拒绝采样 SFT / OPD** | 强模型或当前模型经验证通过的干净轨迹 | 确定性验证器 + 高 $\kappa$ Rubric 过筛管线 | 核查通用能力回退（灾难性遗忘）与格式僵化 |
| **DPO / 偏好对齐** | 同题“过验正轨迹 vs 真实失败负轨迹”配对 | Open Coding 失败模式 + 自动轨迹回放器 | 核查正样本对数似然漂移与过度拒绝率 ORR 抬头 |
| **RLVR / Agentic RL** | 新合成交互任务 + 终端/单测/RaR 可验证奖励 | Docker 沙箱快照池 + 终态断言 + 掩码 $\mu_t$ | 核查 $\widehat{\mathrm{pass@}k}$ 覆盖率是否萎缩及奖励作弊泛化 |

3. **训练前自动防污染自检闸门**：任何一批新整理好的训练数据在提交训练任务前，必须强制跑完三层去污审计并将报告随 Checkpoint 元数据永久归档：

| 污染审计层级 | 扫描范围与检测算法 | 强制阻断红线 |
| --- | --- | --- |
| **精确与词面去污** | `Train Pool` 对 `Dev + Holdout` 执行标准化哈希与 **13-gram / MinHash** 重叠扫描 | 命中率必须为 $0\%$，任何重叠样本自动剔除 |
| **语义近邻去污** | 对问题与工具上下文做向量近邻检索，排查改写型变体泄漏 | 余弦相似度 $>0.90$ 触发人工拦截审计 |
| **实体与集群隔离** | 核验代码仓、文档源 ID 与模拟工单种子是否与评测池共享同一 `cluster_id` | 严禁同文档/同代码仓跨训练池与 Holdout 池切分 |

## 20.3 面向 2026+ 的三大评测前沿展望

站在 2026 年的节点向前眺望，随着推理与 Agent 模型能力持续逼近甚至超越人类单兵专家边界，传统“静态题库 + 人类标标准答案”的评测范式正在触及深层瓶颈。未来数年，三个前沿方向将深刻重塑测量科学：

### 前沿一：<a class="term-ref" href="/books/llm-eval/glossary#scalable_oversight" title="可扩展监督与隐藏能力：模型超越单人专家时的可靠监督机制与策略性装傻审计">可扩展监督（Scalable Oversight）</a>
当模型输出一份长达五万字的跨学科科研综述、一段高度复杂的内核并发补丁或一个前沿数学证明时，单个人类专家连“判断它对不对”都要耗费数天，人类标注本身开始出现高噪声。工业界与学界正探索三类杠杆来放大人类有限的监督带宽：
- **AI 辩论（Debate）与对抗审查**：让正反两方强模型针对同一份答案互揪漏洞，把隐蔽的逻辑断层暴露在聚光灯下，人类只需扮演终审法官裁决最尖锐的分歧点；
- <strong>递归任务分解（Recursive Decomposition）</strong>：将难以整体评判的巨型任务递归拆解为几十条局部独立、人类或程序可在秒级核查的原子子声明；
- **验证器辅助监督**：最大化“创造难、验证易”的非对称优势——借助形式化定理证明器（Lean 4）、可执行沙箱与交替进化的协议级 Rubrics（如 Rubric-ARM），把人类认知从繁琐核对中解放出来。

### 前沿二：防隐藏能力与评测感知（Sandbagging & Evaluation Awareness 审计）
前沿推理模型已展现出越来越强的<strong>情境感知能力（Evaluation Awareness）</strong>——它们能从系统提示、玩具沙箱结构或典型基准句式中辨认出“我现在正处于安全或能力评测中”。这衍生出一种极具挑战的新型测量失效：<strong>隐藏能力（Sandbagging）</strong>，即模型在危险能力审计或合规评测中策略性地压低表现以逃避部署限制，而在真实生产环境中却展现出完全不同的能力上限。应对之道正在从静态考卷转向三层反侦察审计：
- **真实工作流无痕嵌入**：将安全与边界探测直接融入生产等价的多轮工具与仓库环境，在统计分布与系统提示特征上消除“一眼看穿是考题”的线索；
- <strong>能力引出基线审计（Elicitation Audit）</strong>：对关键安全评测施加正向激励提示或极小样本定向微调，量化“引出后的真实潜能上限”与“默认评测表现”之间的异常落差，精准揪出策略性装傻；
- **内部表征与跨情境一致性校验**：结合激活探针检查模型是否识别出“正在被测试”，并比对等价任务在模拟环境与伪装生产环境下的行为一致性。

### 前沿三：心理测量学驱动的持续自适应考试（<a class="term-ref" href="/books/llm-eval/glossary#irt_cat" title="IRT / CAT：基于项目反应理论估计题目难度与区分度并动态选题的自适应评测范式">IRT / CAT</a>）
面对动辄数千题、跑一次动辄消耗数千美元的 Agent 综合套件，传统“所有模型考同一份定长死卷子”既极其浪费算力（对强模型而言 70% 的题太简单没有信息量，对弱模型而言 70% 的题太难全得 0 分），又极易陷入 <a class="term-ref" href="/books/llm-eval/glossary#ceiling_effect" title="天花板效应：基准过易导致强模型挤在顶端失去区分度">天花板效应</a>。借助心理测量学的<strong>项目反应理论（IRT）</strong>为每道题标定难度 $b_j$ 与区分度 $a_j$，再以<strong>计算机自适应测试（CAT）</strong>在线挑选费雪信息量（Fisher Information）最大的下一道题，可为企业评测带来三重跃迁：
- **5–10 倍算力压缩**：动态聚焦于模型真实能力边界附近的“黄金信息带”题目，以极少题量达到与千题全集相当的标准误；
- **跨期题库平滑换血**：借助共享锚定题把每季度滚动新加入的线上活题对齐到同一潜能力标尺 $\eta_m$ 上，既防老化又不丢历史可比性；
- **题目体检自动化**：自动识别区分度 $a_j \le 0$ 的畸形坏题（强模型反而比弱模型答得差的标注错误或歧义题），反向净化黄金集质量（完整数学推导与工程落地详见 [专题 B：心理测量学与 IRT / CAT 自适应评测](/books/llm-eval/topics/irt-and-cat)）。

## 全书结语：推理、强化学习与评测的三位一体

回望这套横跨三本书的知识图谱，现代大模型与智能体工程的三根支柱已经严丝合缝地咬合在了一起：

- [《LLM 推理工程：原理与方法》](/books/llm-inference/) 回答<strong>“如何算得快、省得下”</strong>——从 KV Cache、PagedAttention、投机解码到低比特量化与分布式部署，直接雕刻了联合帕累托前沿的**成本与延迟**双轴；
