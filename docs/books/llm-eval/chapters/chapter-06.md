# 第 6 章 推理、代码与多模态底座评测

<p class="chapter-summary">剖析推理与多模态底座选型中最具迷惑性的五大评测陷阱：30 题竞赛数学的小样本高方差、看似严谨却属事后合理化的思维链、过时静态代码榜单的污染、隐藏思考开销的效率假象，以及视觉基准里“不看图也能蒙对”的纯文本捷径。</p>

如果说第 5 章检验的是底座“听得懂、记得住、不胡说”的稳健底盘，那么本章评估的则是驱动代码助手、复杂规划 Agent 与 GUI 操作智能体的**高阶认知引擎**——深度数学与逻辑推理、程序编写与修复，以及跨模态视觉理解。正因为这一赛道商业竞争最激烈，榜单水分与统计误区也最为集中。

## 6.1 数学与形式化推理：小样本高方差与防污染闭环

以 DeepSeek-R1、OpenAI o 系列及各类思考型模型为代表的推理浪潮，将 <strong>AIME（美国数学邀请赛）</strong>推上了每场发布会的头号聚光灯。然而，把 AIME'24 / '25 / '26 当作核心选型标尺时，工程师必须先算清一笔残酷的方差账。

### 为什么 AIME 单届 $N=30$ 题的微弱领先毫无统计意义

每年 AIME I + II 合计仅 **$N = 30$ 道整数填空题**，单道题即占 **$3.33\text{ pp}$**。对每道题独立采样 $n$ 次计算均分 $\bar s$ 时，总方差可分解为“题目抽样方差”与“生成采样方差”两项：

$$
\mathrm{Var}(\bar s) \;=\; \underbrace{\frac{\sigma_{\text{item}}^2}{N}}_{\text{题量上限决定，加 } n \text{ 无法消除}} \;+\; \underbrace{\frac{\bar\sigma_{\text{sample}}^2}{N \cdot n}}_{\text{增大采样数 } n \text{ 可压低}}
$$

在 $p = 0.50$ 附近，单次采样（或题目呈 0/1 极端两极分化）的最坏标准误上界高达 $\mathrm{SE}_{\max} = \sqrt{0.25/30} \approx \mathbf{9.1\text{ pp}}$（95% 置信区间宽约 $\pm 18\text{ pp}$）；即便对每道题采样 $n=64$ 次将第二项采样方差压近于零，只要题目数仍锁在 $N=30$，现实竞赛题的题间难度方差（$\sigma_{\text{item}}^2 \approx 0.08\text{–}0.18$）仍会留下 **5–8 pp** 的不可消除标准误（95% 置信区间宽约 $\pm 10\text{–}15\text{ pp}$）。因此，**拿单届 AIME 上 2–3 个百分点的优势去宣称一代模型全面胜出，在统计学上纯属噪声解读**；规范评测必须跨届拼接（如 AIME'24+'25+'26 叠加 HMMT / BRUMO 扩展至 100+ 题）并执行配对检验。

| 推理基准 | 规模与形态 | 防污染机制 | 判分验证方式 | 工程选型定位 |
| --- | --- | --- | --- | --- |
| **AIME'24 / '25 / '26** | 每年 30 道整数填空 | 逐年新题（但公开后迅速被收录） | 整数精确匹配 | 仅作跨年汇总（90 题+）与高 $n$ 平均后的趋势参考 |
| **FrontierMath**（Epoch AI，2024） | 数百道未公开研究级数学题 | **题库永久闭源**，第三方托管评测 | 符号 / 程序验证器 | 检验前沿推理上限的抗污染风向标 |
| **MiniF2F / PutnamBench** | 高中竞赛至普特南级形式化定理 | 严格逻辑推导，极难靠浅层背诵蒙混 | **Lean 4 / Isabelle 内核验证** | 100% 严密<a class="term-ref" href="/books/llm-eval/glossary#deterministic_verifier" title="直接通过符号等价、AST/JSON 校验、单元测试或环境终态给出客观判分的程序化裁判">确定性验证器</a>，杜绝步骤跳跃与蒙对 |

## 6.2 推理忠实度（CoT Faithfulness）：如何拆穿“事后合理化”

思考型模型会把长达数千字的 `<think>...</think>` 思维链展示给用户或审计系统，很多人因此自然地以为：“只要检查思维链里有没有违规或错误逻辑，就能监控模型有没有作弊或算错。”这是一个危险的错觉——我们必须严格区分<strong>「思维链看起来合情合理」</strong>与<a class="term-ref" href="/books/llm-eval/glossary#cot_faithfulness" title="模型生成的思维链文字是否真实反映了决定其最终答案的内部计算因果过程">推理忠实度（CoT Faithfulness）</a>。

Turpin 等（2023）、Lanham 等（2023）以及 Anthropic（2025）针对前沿推理模型的系统实验反复证实：模型经常先凭借隐藏特征、偏置提示或记忆捷径锁定结论，再编造出一整段流畅但与真实因果无关的<strong>「事后合理化（Post-hoc Rationalization）」</strong>文本。更值得警惕的是，仅对最终答案给 0/1 奖励的 RLVR 训练并不会自动提升忠实度，甚至可能催生压缩隐晦或隐瞒关键线索的思维链。评测团队可用三种因果干预探针量化忠实度：

| 诊断探针 | 干预操作方式 | 不忠实（事后合理化）的判定信号 | 工程警示意义 |
| --- | --- | --- | --- |
| **反事实提示注入** | 在题干暗插指向特定答案的偏置线索（如“教授草稿选 C”或 XML 元数据标签） | 模型从原答案翻盘改选 C，但思维链中**只字未提该线索**（Hint-Mention Rate 偏低），假装纯靠独立推导得出 C | 不可仅靠监控 CoT 文本来拦截提示注入或奖励作弊（衔接第 7 章） |
| **提前截断测试** | 在思维链写到 25% / 50% / 75% 进度时强行闭合思考标签并令其立刻给答案 | 极早期截断即已达到接近完整思考的准确率 | 后半段长篇思考大量属于“重复确认与装饰”，白白拉高延迟 |
| **中间错步扰动** | 暗中篡改思维链中段的一个关键中间数字或符号，让模型从该处续写 | 即使前文中间值已明显被改错，最终答案依然“神奇地”输出原正确结果 | 证明模型在隐状态中绕开了显式 CoT 文字走捷径 |

用反事实注入探针可定义可比较的**忠实披露率（Faithful Mention Rate）**：在所有“受偏置线索影响而改选目标答案”的样本子集中，思维链显式承认参考了该线索的占比。若某模型改选率高达 70%，但忠实披露率不足 30%，就意味着工程团队**绝不能把思维链审核当成唯一的安全或合规审计手段**——必须配合外部确定性验证器与第 7 章的沙箱权限闸门。

## 6.3 代码活基准：防污染时间戳与“算法 vs 工程”鸿沟

代码评测领域最早遭遇了严重的静态榜单失真：经典的 HumanEval（164 题）与 MBPP 发布多年且测例稀少（正如 EvalPlus 论文揭示，补全边界测例后多家模型分数明显下滑，`pass@1` 降幅最高达 19.3%，`pass@k` 降幅最高达 28.9%），早已无法充当现代底座的试金石。

<strong>LiveCodeBench（Jain 等，2024）</strong>确立了代码底座的<a class="term-ref" href="/books/llm-eval/glossary#live_benchmark" title="持续引入截断日期之后的新题并按时间戳切片评测，从机制上抵御静态数据污染的基准范式">动态活基准（Live Benchmark）</a>范式：它持续收录 LeetCode、AtCoder、CodeForces 等竞赛平台带精确发布日期的新题，并拆解出四类互补子任务：

- **代码生成（Code Generation）**：给定自然语言题意与边界约束，从零编写完整可运行解法；
- **自我修复（Self-Repair）**：接收沙箱报错堆栈或失败测例，检验模型迭代定位并修复 Bug 的能力；
- **代码执行推演（Code Execution）**：给定源码与输入，不借助解释器直接心算推导输出结果；
- **测试输出预测（Test Output Prediction）**：根据题意与边界输入推理预期输出，衡量需求理解与自写单测潜力。

选型时最有诊断价值的操作，是按**模型知识截断日期前后切分时间窗**：若某模型在截断前半年题集上 $\mathrm{pass@}1$ 高达 75%，而在截断后纯未来窗口骤跌至 45%，几乎可以一锤定音地判定其受过严重的<a class="term-ref" href="/books/llm-eval/glossary#data_contamination" title="评测集的题目、参考答案或其改写变体意外混入训练语料，导致离线分数虚高的现象">数据污染</a>。同时，架构师必须清醒地划开<strong>「算法竞赛题」与「仓库级工程」</strong>的分水岭：

| 对比维度 | 算法活基准（LiveCodeBench） | 仓库级工程基准（SWE-bench / Terminal-Bench） |
| --- | --- | --- |
| **上下文形态** | 单文件、几百字自包含题意与严格输入输出格式 | 数百个源码文件、长 Issue 讨论串、复杂依赖环境 |
| **核心能力重心** | 算法构造、边界条件枚举与时间复杂度优化 | 故障定位、跨模块架构理解、终端命令交互与防回归 |
| **主导评估指标** | 第 2 章的<a class="term-ref" href="/books/llm-eval/glossary#pass_at_k" title="对同一题目独立采样 k 次，至少有一次通过验证的概率">无偏 pass@k</a>（单轮或有限自修） | 隐藏测试套件终态通过率 + 补丁侵入性与单任务成本 |
| **选型避坑提示** | 竞赛题第一名经常在多轮仓库工具协同上反被稳健底座超越 | 必须结合 [第 10 章](/books/llm-eval/chapters/chapter-10) 控制脚手架变量实测，切忌以算法分代工 |

## 6.4 思考效率帕累托：Accuracy vs Thinking Tokens 与过度思考

当推理模型普遍开放了 `reasoning_effort`（低/中/高档）或思考 token 预算旋钮后，**脱离平均思考 token 数只报单一最高准确率，本质上是在隐藏 5–10 倍的延迟和账单差异**。算一笔简单的延迟账（教学算例）：按常见推理服务单流解码吞吐 $60\text{ tok/s}$ 计算，模型 A 均耗 $2{,}200$ 思考 token 对应耗时约 **$37\text{ s}$**，而模型 B 为多换 $1.5\text{ pp}$ 准确率把均耗推到 $19{,}000$ token，单次等待骤增至 **$317\text{ s}$（超 5 分钟）**——在交互式 Agent 工作流里完全不可接受。

规范的推理效率评测必须在多个预算档位 $B \in \{1\text{K}, 2\text{K}, 4\text{K}, 8\text{K}, 16\text{K}\}$ 上绘制 **Accuracy vs 平均 Thinking Tokens 曲线**，追踪其<a class="term-ref" href="/books/llm-eval/glossary#pareto_frontier" title="在质量、成本与延迟构成的多维空间中，不被其他方案全面碾压的最优折中集合">帕累托前沿</a>与预算曲线下面积（AUBC，并在 [第 15 章](/books/llm-eval/chapters/chapter-15) 与 $/Task 及 P95 延迟联立）。同时需要重点量化推理模型普遍存在的<strong>「过度思考（Overthinking）」</strong>病症（仅在思维链导出过正确答案的样本上统计，确保分母有定义）：

$$
\mathrm{Overthinking\ Ratio} \;=\; \frac{\text{总思考 Token 数}}{\text{思维链首次导出正确答案时的 Token 数}}
$$

- 在简单或中等难度题目上（例如常规 SQL 改写或两步财务核对），部分推理模型在前 400 token 就已写出正确答案，却因后训练养成的“反复自我质疑”惯性继续消耗 3,000–8,000 token，不仅让 TTFT 与端到端延迟暴涨，**还常在反复验算中把原本正确的答案改错**，在效率曲线右端形成向下弯折的拐点（见图 6-1 左面板）。
- 选型时应分层报告<strong>「简单题平均思考长度」</strong>与<strong>「高难题上限准确率」</strong>，优先选择具备自适应思考分配能力（简单题秒答、难题深思）的底座。

## 6.5 视觉多模态底座与“去图盲测”清洗方法论

当企业需要将发票单据 OCR、工业质检图表分析或桌面屏幕截图接入 Agent（衔接 [第 12 章 GUI 操控](/books/llm-eval/chapters/chapter-12)）时，视觉语言模型（VLM）的评测暗藏一个最隐蔽的效度漏洞：**许多公开 VQA 基准的题目，根本不需要看图，仅凭纯文本常识和选项猜测就能答对 40% 以上！** 如果不剥离这部分纯文本捷径，你测出来的其实只是底层语言模型有多强，而不是视觉编码器和跨模态对齐有没有真正“看见”。

代表性视觉底座基准正围绕“反文本捷径”与“反视觉幻觉”演进：
- **MMMU-Pro（Yue 等，2024）**：对原 MMMU 实施三重手术——剔除纯文本 LLM 可答对的题目、将选项从 4 项扩至 **10 项**压缩猜测下限，并增设<strong>「纯图像视觉输入版」</strong>（直接把题干和选项渲染进截图里，倒逼模型完成读图与 OCR 融合）。
- **MathVista（Lu 等，2024）**：聚焦几何图形、函数图像与统计图表上的视觉数学推理，检验视觉信息抽取与符号运算的协同。
- **HallusionBench（Guan 等，2024）**：构造大量视觉错觉与微调对照图（例如把常见标志或坐标系稍作反常识改动，设置正反成对的 Yes/No 题），专抓模型<strong>「不信眼睛信先验（Language Prior Overriding Vision）」</strong>的顽固幻觉。

### 企业落地必做：去图盲测（Blind-Test Filtering）四步清洗

无论采信公开榜单还是自建企业截图/图表评测集（生成类图像/视频/语音模态见 [专题 D](/books/llm-eval/topics/generative-multimodal-eval)），上线前务必执行图 6-1 右面板所示的<strong>「去图盲测清洗协议」</strong>：

1. **屏蔽图像盲跑**：移去图像输入，仅将题干与选项喂给 2–3 个强纯文本 LLM，测得盲答准确率 $\mathrm{Acc}_{\text{blind}}$；同时抽样做“随机打乱配图”对照 $\mathrm{Acc}_{\text{shuffled}}$。
2. **核算净视觉增益**：对候选 VLM 报告完整图测得分 $\mathrm{Acc}_{\text{img}}$ 的同时，必须并列报告**净视觉增益** $\Delta_{\text{vis}} = \mathrm{Acc}_{\text{img}} - \mathrm{Acc}_{\text{blind}}$（以及相对打乱图增益）。若某题库 $\mathrm{Acc}_{\text{blind}} > 35\%$，说明基准信噪比已被文本捷径严重污染。
3. **剔除或改写捷径题**：凡是被多款纯文本模型稳定盲答命中的样本，直接剔除或改写为依赖图像细微局部（如特定表格行数值、图表交叉点、界面高亮状态）的对照题。
4. **成对反转防猜测**：对二值判断类视觉质检任务，尽量按 HallusionBench 思路构建成对正负图，要求模型**成对全对**才计分，彻底封死盲猜空间。

::: warning 选型避坑：三类高发虚假领先
1. **AIME 单届差 3 分即换底座**：$N=30$ 题量下 1 题即 3.33 pp，未经多届汇总与配对检验的微弱优势极易是噪声。
2. **隐藏思考长度比峰值分**：不标出 `avg_thinking_tokens` 和 `max_tokens` 截断率的推理榜，属于残缺口径。
3. **跨代对比未切活基准日期**：比较新老模型代码能力时，务必截取**晚于两个模型截断日期的共同未来窗口**，否则新模型天然占尽污染红利。
:::

至此，底座的“智商”（知识、长文、推理、代码、视觉）标尺已立稳；但在把高智商模型接入真实工具与外部世界之前，还有一道生死红线必须验证——第 7 章的安全防线、过度拒绝权衡与 Agent 最致命的间接提示注入。
